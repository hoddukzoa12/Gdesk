# 시스템 구성

## 전체 모양

Gdesk는 서버가 없는 Electron 앱 하나다. 프로세스 셋과 외부 시스템 몇 개로 이루어진다.

```
┌──────────────── 화면(renderer) ────────────────┐
│ React + react-query + i18n                     │
│ 격리됨: contextIsolation, sandbox, Node 없음    │
└───────────────▲───────────────┬────────────────┘
                │ 이벤트 on     │ invoke
┌───────────────┴───────────────▼────────────────┐
│ 프리로드: window.gdesk = { invoke, on } 두 개뿐  │
└───────────────▲───────────────┬────────────────┘
                │ ipcRenderer   │ ipcMain.handle
┌───────────────┴───────────────▼────────────────┐
│ 메인 프로세스                                    │
│  IPC 처리기 ─┬─ 조회(캐시 읽기만)                 │
│              ├─ 쓰기 동작 ── GitHub 요청 계층 ───┼──► api.github.com (GraphQL·REST)
│              ├─ 로그인 ───── 기기 인증 ──────────┼──► github.com/login/*
│              ├─ 로컬 연결·클론 ─ 내장 git ───────┼──► github.com (git HTTPS/SSH)
│              ├─ 오류 보고 ─── 브라우저 열기 ─────┼──► 기본 브라우저 (새 이슈 페이지)
│              └─ 업데이트 ─── electron-updater ──┼──► GitHub Releases
│  동기화 엔진 ── 수집기 ── GitHub 요청 계층       │
│  SQLite(userData/gdesk.db)  토큰 저장소(userData/auth/, OS 보안 저장소) │
└────────────────────────────────────────────────┘
```

- 화면은 표시와 사용자 입력만 맡는다. GitHub 호출, git 실행, DB·파일 접근, 토큰은 모두 메인 프로세스에 있다.
- 화면과 메인 사이를 오가는 것은 타입이 정해진 요청·응답과 이벤트의 평범한 값뿐이다. 토큰, 오류 원문 객체, 파일 핸들은 넘어가지 않는다.
- 화면이 보는 데이터는 언제나 로컬 DB 캐시에서 읽은 것이다. GitHub 응답이 화면으로 바로 가지 않는다. 그래서 오프라인·재시작 직후에도 마지막 정보가 보인다.

## 시작 순서

`src/main/index.ts`의 순서에는 의존이 있다.

1. 테스트 모드면 사용자 데이터 폴더를 바꾼다. 이동 막기를 설치하고 처리되지 않은 오류 수집을 시작한다(창이 생기기 전 오류도 보관).
2. `app.whenReady()` 뒤:
   1. DB를 열고 마이그레이션한다.
   2. 캐시 정리 함수를 계정 단위 삭제에 등록한다.
   3. 로그인 서비스를 만들고 저장된 토큰을 읽는다(OS 보안 저장소는 ready 이후에만 쓸 수 있다).
   4. GitHub 요청 계층을 만든다(토큰은 로그인 서비스의 공급 함수로 얻는다).
   5. 모든 IPC를 등록한다. 쓰기 동작 처리기는 등록할 때 요청 계층을 구독하므로 4가 먼저여야 한다.
   6. 앱 메뉴를 설치하고, 고정 변경을 `data:changed`로 잇는다.
   7. 요청 계층의 401을 구독하고, 테스트 모드면 환경 변수 토큰으로 자동 로그인할 때까지 기다린다. 아니면 저장된 토큰을 뒤에서 다시 확인한다.
   8. 동기화 엔진을 만든다. 창 생성을 잡아야 하므로 첫 창보다 먼저다.
   9. 메인 창을 만들고, 업데이트 확인과 로컬 폴더 자동 찾기를 뒤에서 시작한다.

## 대표 흐름

### 저장소 상세 화면 열기

1. 화면이 `#/repos/<ID>`로 이동하고 `query:repoDetail`로 캐시를 읽는다. 캐시에 행이 없으면 `null`이다.
2. 화면이 `sync:setViewedRepo`로 진입을 알린다. 엔진은 그 저장소를 상세 추적 집합에 넣고, `signed_in` + `online`이면 곧바로 상세를 받는다(응답을 기다리지 않고 IPC는 바로 끝난다).
3. 수집기: 캐시에 GraphQL 노드 ID가 없으면 `GET /repositories/{ID}`로 찾는다 → `GdeskRepositoryDetail` GraphQL 1회 → 기여자 REST 1~2회 → 스타 시각 REST를 최신 페이지부터 거꾸로.
4. 한 트랜잭션으로 캐시에 저장하거나, 접근 불가면 `unavailable`로 표시한다.
5. 엔진이 `data:changed`(`repo:<ID>`, `home`, `sidebar`)를 모든 창에 보낸다. 화면은 `query:`로 시작하는 조회를 모두 다시 읽는다.
6. 화면을 떠나면 `sync:setViewedRepo`에 `null`을 보내 추적을 끝낸다.

### 스타 누르기

1. 화면 → `actions:star { repoId, starred }`.
2. 메인: 같은 저장소의 이전 동작이 끝나기를 기다린다 → 세션·연결 상태로 막힘 판단 → 캐시의 스타 여부·수를 바꾸고 `data:changed` → `PUT`/`DELETE /user/starred/...`.
3. 실패하면 캐시를 이전 값으로 되돌리고 다시 `data:changed`를 보낸 뒤 실패를 돌려준다. 화면은 다시 읽은 값으로 원래 모습이 된다.

### 이슈 상세 패널 열기

1. Issues 화면에서 행을 누르면 주소에 `issue=<저장소 ID>-<번호>`가 붙고 패널이 `query:issueDetail { repoId, number }`로 캐시를 읽는다. 받은 적이 없으면 `null`이다.
2. 패널이 `sync:setViewedIssue { repoId, number }`로 보고 있다고 알린다. 엔진은 그 이슈를 기억하고, `signed_in` + `online`이면 곧바로 받는다(IPC는 기다리지 않고 끝난다). 같은 이슈를 다시 알리면 받지 않는다.
3. 수집기: 저장소 이름을 캐시(저장소 행, 없으면 이슈 행)에서 찾고, 없으면 `GET /repositories/{ID}` → `GdeskIssueDetail` GraphQL 1회(본문·코멘트 `bodyHTML`, 반응, 닫는 PR, 연결·참조 타임라인, `viewerCan*`, 저장소 권한).
4. 계정 세대를 확인한 뒤 `cache_issue_details`에 JSON 한 덩어리로 쓴다(200개 넘으면 오래 받은 것부터 지움). 이슈를 찾을 수 없으면 이전 상세를 둔다.
5. 엔진이 `data:changed`(`issues`, `issue:<저장소 ID>#<번호>`)를 보낸다. 화면은 다시 읽어 HTML을 DOMPurify 전용 인스턴스로 정리한 뒤 넣는다.
6. 패널이 열려 있는 동안 목록 주기와 `issues` 수동 새로고침이 그 이슈를 다시 받는다. 패널을 닫거나 화면을 떠나면 `null`을 보낸다. 로그아웃·계정 전환이면 엔진이 스스로 잊는다.

### 이슈 쓰기

1. 화면 → `issueActions:react`·`comment`·`setState`·`create`.
2. 메인: 요청 모양 검사(어긋나면 거부) → 같은 이슈(새 이슈는 같은 저장소)의 앞 동작을 기다린다 → 막힘 판단 → 캐시된 상세의 `viewerCan*`·코멘트 가능 여부로 거절 판단.
3. 반응·닫기·다시 열기: 상세 캐시를 먼저 바꾸고 `data:changed`(`issues`, `home`, `issue:<저장소 ID>#<번호>`) → GraphQL mutation(`GdeskAddReaction`·`GdeskRemoveReaction`·`GdeskCloseIssue`·`GdeskReopenIssue`) → 실패하면 바꾸기 전 상세로 되돌리고 다시 알린다. 닫기·다시 열기가 성공하면 엔진의 `refresh('issues')`를 기다리지 않고 부른다.
4. 코멘트: `GdeskAddComment` → 성공하고 계정 세대가 그대로면 상세에 붙인다.
5. 새 이슈: 요청 계층의 REST `post`로 `POST /repos/{소유자}/{이름}/issues` → 성공하고 세대가 그대로면 `cache_created_issues`에 기록하고 "내 이슈" 범위에 넣은 뒤 `data:changed`(`issues`, `home`). 다음 검색 목록 갱신은 이 기록을 보고 10분 동안 이슈를 남긴다.
6. 라벨·담당자 선택지는 `GET .../labels`·`.../assignees`(페이지 상한), 미리보기는 `POST /markdown`(텍스트 응답)을 그때그때 부르고 캐시하지 않는다.

### Home 활동 영역

- 목록 주기 끝(`home` 수동 새로고침에서도)에 `GdeskContributions` GraphQL로 기여 달력과 커밋 기여 수를 받아 `cache_contribution_days`·`cache_contribution_summary`를 통째로 바꾼다.
- 이어서 REST 커밋 검색 `GET /search/commits?q=author:<로그인>&sort=author-date&order=desc`로 최근 커밋을 받아 `cache_recent_commits`를 통째로 바꾼다. 이 요청은 search 한도를 쓰며, 자동 갱신에서는 search 한도가 적으면 이것만 건너뛴다. 로그인 이름은 로그인 서비스의 세션에서 얻는다.
- `query:home`은 할 일 카드 집계에 활동 영역을 더해 돌려준다. 수치는 기여 달력, 내 저장소 집합, 내가 올린 PR 목록의 전체 수에서 계산하고, 근거 범위를 한 번도 받지 않았으면 `null`이다.

### 자동 갱신 한 바퀴

동기화 엔진은 창 열림 + `signed_in` + `online`일 때만 알림(60초)·목록(5분)·상세(5분) 타이머를 돌린다. 각 갱신은 수집기의 `refresh*`를 부르고, 끝나면 마지막 동기화 시각을 바꾸고 해당 키로 `data:changed`를 보낸다. 연결 상태 변화는 요청 계층이 알리고, 엔진은 그때마다 타이머를 켜고 끈다. 오프라인이면 30초마다 `GET /rate_limit`로 연결을 확인한다.

| 대상                      | 쓰는 곳              | 방식                                                                                                                                                                                                                                                                                                           |

## 경계에서 넘어가는 것과 넘어가지 않는 것

| 경계                        | 넘어가는 것                                                                                                                                                                 | 넘어가지 않는 것                                                     |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 화면 → 메인                 | 채널 이름과 평범한 요청 값. 로그인 화면에서 입력한 토큰은 `auth:loginWithToken`으로 한 번 넘어간다. 연결·다시 연결·클론 대상에는 절대 경로를 보낸다.                        | 열기 대상 경로(열기는 연결 ID로만 한다), GitHub에 보낼 임의 URL·헤더 |
