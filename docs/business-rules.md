# 업무 규칙

숫자 기본값 중 "조정 가능"이라고 적은 것은 코드 상수나 함수 옵션으로 바꿀 수 있다는 뜻이다. 설정 화면에서 사용자가 바꾸는 값은 아래 "설정" 절에 나오는 여섯 항목뿐이다.

## 용어

| 용어             | 정의                                                                                                                                                    | 혼동 주의                                                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 계정             | 로그인한 github.com 사용자 1명. 숫자 사용자 ID로 식별한다.                                                                                              | 앱은 동시에 계정을 하나만 가진다. GitHub Enterprise Server 계정은 현재 받지 않는다.                                    |
| 내 저장소 집합   | 내가 `ADMIN`·`MAINTAIN`·`WRITE` 권한을 가진 저장소. 소유·협업자·조직 멤버 저장소를 모두 훑은 뒤 이 권한으로 거른다. 비공개·포크·보관 저장소도 들어간다. | `TRIAGE`·`READ`만 있는 저장소는 조직 저장소여도 빠진다. "내 저장소"는 언제나 이 집합이다.                              |
| 들어온 PR·이슈   | 내 저장소 집합의 열린 PR·이슈 중 내가 작성하지 않은 것                                                                                                  | "내가 올린"은 저장소를 가리지 않는다. 남의 저장소에 올린 PR도 들어간다.                                                |
| 고정(Pin)        | 앱 안에만 저장하는 저장소 즐겨찾기. 숫자 저장소 ID와 순서만 저장한다.                                                                                   | GitHub 프로필의 pinned repositories와 무관하다. 동기화하지 않는다.                                                     |
| 상세 추적 저장소 | 고정 저장소 전부 + 지금 상세 화면에 열려 있는 저장소 1개                                                                                                | 커밋·CI·릴리스·기여자·언어·스타 시각은 이 저장소들만 받는다.                                                           |
| 로컬 연결        | (저장소 ID, 폴더 경로) 한 쌍. 저장소 하나에 여러 폴더를 연결할 수 있다.                                                                                 | 연결을 지워도 폴더는 남는다.                                                                                           |
| 쓰기 동작        | 스타·스타 취소, 알림 읽음, 알림 완료, 이슈 반응·코멘트·닫기·다시 열기, 새 이슈                                                                          | 클론, 새 이슈 양식의 라벨·담당자 받기, 마크다운 미리보기는 쓰기가 아니지만 같은 막힘 조건(로그인 + `online`)을 따른다. |
| Home 영역        | Home 인사말 아래의 열 개 영역: 활동 영역 다섯(수치, 고정 저장소, 기여 달력, 최근 커밋, 내 PR) + 할 일 카드 다섯                                         | 인사말은 영역이 아니다(늘 맨 위, 끌 수 없음). 설정 키 이름은 예전 그대로 `homeCards`다.                                |
| 받아온 정보      | GitHub에서 받아 로컬 DB에 둔 캐시 전체                                                                                                                  | 고정·로컬 연결·설정·마지막 로그인 사용자 ID는 받아온 정보가 아니다.                                                    |

## 식별

- 저장소, 고정, 로컬 연결은 모두 GitHub 숫자 저장소 ID로 식별한다. 이름(`소유자/이름`)으로 저장하거나 이름으로 고정·연결을 찾지 않는다.
- 저장소 이름이 바뀌거나 다른 소유자로 옮겨지면, 다음에 그 저장소를 받을 때 같은 ID 행의 이름이 바뀐다. 고정과 연결은 그대로 따라간다.
- PR·이슈는 GraphQL 노드 ID로, 알림은 GitHub 스레드 ID로 식별한다.
- 이슈 상세와 이슈 쓰기 동작은 (숫자 저장소 ID, 이슈 번호)로 이슈를 가리킨다. 노드 ID와 내 권한은 상세를 받은 뒤 캐시에서 얻는다. 저장소 이름은 캐시(저장소 행, 없으면 그 저장소의 이슈 행)에서 찾고, 없으면 `GET /repositories/{id}`로 묻는다.

## 저장소 접근 상태: `available` / `unavailable`

- GitHub 응답에 저장소가 담겨 오면 그 저장소는 `available`이 된다.
- 다음 중 하나면 `unavailable`이 된다.
  - 상세 수집에서 404·410(삭제), 403·451(권한 상실), 조직 접근 제한을 받거나 GraphQL `node`가 비어 온 경우
  - 내 저장소 집합을 완전히 받았는데 이전에 집합에 있던 저장소가 빠졌고, 그 저장소가 고정됐거나 로컬 폴더에 연결돼 있으며, `GET /repositories/{id}`가 404·410·403·451 또는 조직 접근 제한으로 실패한 경우.
- 위 확인이 성공하면(쓰기 권한만 잃은 공개 저장소 등) `available`로 둔다. 다른 실패(오프라인·한도·세션 만료·5xx)면 상태를 바꾸지 않고 남은 확인도 멈춘다. 연결만 된 저장소는 상세 수집을 받지 않으므로, 집합에서 빠질 때의 이 확인만으로 상태가 정해진다. 고정 저장소는 다음 상세 수집에서 받아지면 다시 `available`이 된다.
- `unavailable`이 되어도 고정과 로컬 연결을 자동으로 지우지 않는다. 화면은 사이드바 고정 항목과 설정의 연결된 폴더 목록에 "사용할 수 없음" 표시와 제거(연결 해제) 버튼을 보여 준다. `local:listLinks`는 캐시의 접근 상태를 `accessStatus`로 함께 준다(캐시에 없는 저장소는 `available`).
- 캐시에 행이 아직 없는 고정 저장소(검색에서 고정한 직후, 로그아웃 뒤 남은 고정 등)는 사이드바에 이름 대신 `#<ID>`와 "아직 불러오지 않음"으로 보이고, "사용할 수 없음" 배지 없이 제거 버튼이 있다. 데이터상 접근 상태는 `unavailable`이다. 다음 상세 수집이 숫자 ID로 저장소를 찾아 채운다.

## 내 저장소 집합 갱신

- 페이지당 100개씩 최대 30페이지(3000개)까지 받는다.
- 모든 페이지를 받았을 때만 집합을 통째로 바꾼다. 받은 저장소는 집합에 넣고, 빠진 저장소는 집합에서 뺀다. 행은 지우지 않는다.
- 조직 접근 제한으로 중간에 끊겼거나 페이지 한도에 닿으면 받은 저장소의 머리글만 갱신한다. 집합에서 아무것도 빼지 않는다.
- 권한을 잃은 저장소는 다음 완전한 갱신 때 집합에서 빠진다.

## 고정

- 어떤 저장소든 고정할 수 있다. 내 저장소 집합 밖의 저장소, 스타한 저장소, 검색 결과도 된다.
- 고정하면 목록 맨 끝에 붙는다. 이미 고정된 저장소를 다시 고정하면 아무것도 바뀌지 않는다.
- 순서는 항상 0부터 빈틈없이 이어진다. 해제하면 남은 고정의 순서를 다시 매긴다.
- 순서 바꾸기는 지금 고정 목록과 정확히 같은 ID 집합을 받아야 한다. 빠지거나 더해진 ID, 중복이 있으면 거부하고 아무것도 바꾸지 않는다.
- 고정이 바뀌면 새로 추적 대상이 된 저장소의 상세를 바로 받는다. 단, 자동 갱신이 돌고 있고 상세 갱신이 미뤄지지 않은 경우에만 그렇다.

## 로그인과 세션

### 로그인 방식

- 브라우저 코드 로그인(기기 인증): 빌드에 들어간 공개 client ID가 비어 있지 않을 때만 보인다. 빌드 때 `GDESK_GITHUB_CLIENT_ID`가 없으면 내장 기본값(Gdesk OAuth App)이, 값이 있으면 그 값이 들어간다. 빈 값(`GDESK_GITHUB_CLIENT_ID=`)으로 빌드하면 client ID가 비어 토큰 입력만 보인다.
- 토큰 직접 입력: 앞뒤 공백을 지운 뒤 `GET /user`로 확인한다. 빈 문자열은 요청 없이 `empty_token`으로 거부한다.

### 토큰 종류 판정

| 조건                                 | 종류                 |
| ------------------------------------ | -------------------- |
| `github_pat_`로 시작                 | 세분화(fine-grained) |
| 기기 인증으로 받았거나 `gho_`로 시작 | OAuth                |
| `X-OAuth-Scopes` 헤더가 없음         | 세분화               |
| 그 밖                                | 기본(classic)        |

### 권한 부족 판정

요청 권한은 `repo`, `read:org`, `notifications`다. 권한이 모자라도 로그인은 허용하고, 빠진 권한과 영향을 화면에 알린다.

| 빠진 권한       | 이것 중 하나라도 있으면 충족         | 동작하지 않는 것          |
| --------------- | ------------------------------------ | ------------------------- |
| `repo`          | `repo`                               | 비공개 저장소, 스타       |
| `read:org`      | `read:org`, `write:org`, `admin:org` | 조직 저장소, 팀 리뷰 요청 |
| `notifications` | `notifications`, `repo`              | Inbox                     |

- 세분화 토큰은 권한 목록이 없으므로 빠진 권한을 계산하지 않는다. 대신 Inbox는 언제나 쓸 수 없다.
- Inbox를 쓸 수 없으면 알림을 받지 않고, Inbox 화면에 목록 대신 안내를 보여 준다.

### 기기 인증 상태

`requesting` → `pending` → 성공(로그인) / `expired` / `denied` / `cancelled` / `error`.

- GitHub가 준 간격으로 묻는다. `slow_down`을 받으면 간격을 5초 늘린다. GitHub가 더 긴 간격을 주면 그 값을 따른다.
- 대기 중 잠깐의 네트워크 실패는 만료 시각 전까지 다시 묻는다.
- 취소하거나 새 로그인을 시작하면 이전 시도의 늦은 결과는 버린다.
- 실패·취소·만료되면 시도 전 상태(로그아웃 또는 세션 만료)로 돌아간다.

### 세션 상태 전이

| 지금 상태    | 사건                                               | 다음 상태    | 데이터 처리                                                                           |
| ------------ | -------------------------------------------------- | ------------ | ------------------------------------------------------------------------------------- |
| `signed_out` | 로그인 성공, 마지막 로그인 사용자 ID가 없거나 같음 | `signed_in`  | 아무것도 지우지 않는다.                                                               |
| `signed_out` | 로그인 성공, 마지막 로그인 사용자 ID와 다름        | `signed_in`  | 받아온 정보, 고정, 로컬 연결(DB 행)을 먼저 지운다. 설정은 남긴다.                     |
| `signed_in`  | GitHub 응답 401                                    | `expired`    | 아무것도 지우지 않는다. 저장된 정보를 읽기 전용으로 계속 보여 준다.                   |
| `expired`    | 다시 로그인 성공                                   | `signed_in`  | 위 두 줄과 같은 규칙으로 계정이 같은지 판정한다.                                      |
| 아무 상태    | 로그아웃                                           | `signed_out` | 토큰과 받아온 정보를 지운다. 고정, 로컬 연결, 설정, 마지막 로그인 사용자 ID는 남긴다. |

- 마지막 로그인 사용자 ID는 로그아웃해도 지우지 않는다. 다음 로그인이 다른 계정인지 이것으로 판정한다.
- `expired` 동안 막히는 것: 쓰기 동작, 클론, 자동 갱신, GitHub 저장소 검색. 다시 로그인하기 전에는 GitHub 요청을 보내지 않는다.
- 어떤 경우에도 디스크의 클론 폴더와 사용자 폴더는 건드리지 않는다.
- 앱을 다시 켜면 저장된 토큰으로 네트워크 확인 없이 `signed_in`으로 시작하고, 뒤에서 `GET /user`로 다시 확인한다. 이때 401이면 `expired`가 되고, 오프라인이면 저장된 정보를 그대로 쓴다. 확인에 성공하면 받은 사용자 정보(이름·아바타·공개 이메일)로 저장된 기록을 바꾼다. 토큰을 저장하지 않은 로그인(메모리만)은 이때도 저장하지 않는다.
- 세션 사용자 정보의 이메일은 GitHub 프로필의 공개 이메일(`GET /user`의 `email`)이다. 공개하지 않았으면 없다. email 권한은 요청하지 않는다.
- 로그아웃하거나 계정이 바뀌면 동기화 엔진은 보고 있던 저장소와 이슈 상세 대상도 잊는다. 화면이 다시 알리기 전에는 이전 계정이 보던 저장소·이슈를 받지 않는다.

## 조직 접근 제한

- 조직이 OAuth 앱 접근을 막았거나 SAML 인증을 요구하는 응답을 받으면, 수집 전체를 실패로 보지 않고 조직별 안내로 기록한다. 같은 조직은 최신 기록으로 덮어쓴다. 조직 이름을 알 수 없으면 한 줄로 모은다.
- 확실한 문구나 `X-GitHub-SSO: required` 헤더가 있을 때만 조직 제한으로 본다. 그 밖의 403은 일반 오류다.
- 안내가 지워지는 때: 내 저장소 집합을 완전히 받았는데 이번에 제한이 나오지 않은 조직, 또는 그 조직 소유 저장소의 상세를 성공적으로 받은 경우.

## 연결 상태

값은 `online`, `offline`, `rate_limited`, `session_expired` 중 하나다. 원인이 겹치면 `session_expired` > `offline` > `rate_limited` > `online` 순으로 하나만 표시한다. GitHub 요청 계층이 유일한 출처이며 다른 곳은 구독만 한다.

| 원인                                                | 상태                                | 풀리는 조건                                                                              |
| --------------------------------------------------- | ----------------------------------- | ---------------------------------------------------------------------------------------- |
| 401 응답, 또는 토큰 없이 요청                       | `session_expired`                   | 다시 로그인                                                                              |
| 네트워크 오류, 또는 응답 헤더가 30초 안에 오지 않음 | `offline`                           | 어떤 응답이든 받음. 오프라인 동안 30초마다 `GET /rate_limit`(한도 소모 없음)로 확인한다. |
| 403·429와 `retry-after`                             | `rate_limited`(2차 제한, 모든 자원) | `retry-after`초 뒤                                                                       |
| 403·429와 남은 양 0                                 | `rate_limited`(그 자원만)           | `x-ratelimit-reset` 시각                                                                 |
| 403·429와 "secondary rate limit" 문구만             | `rate_limited`(모든 자원)           | 60초 뒤                                                                                  |
| GraphQL 오류 `RATE_LIMITED`                         | `rate_limited`(graphql)             | reset 시각, 없으면 60초 뒤                                                               |

- 한도는 자원(core·graphql·search·code_search)마다 따로 센다. 같은 범위에 더 늦게 풀리는 막힘이 이미 있으면 그것을 유지한다.
- 막힌 동안 같은 자원의 요청은 GitHub에 보내지 않고 바로 거절한다.

## 자동 갱신

### 언제 도는가

자동 갱신은 다음이 모두 참일 때만 돈다. 하나라도 거짓이면 다음 주기를 잡지 않는다. 이미 진행 중인 요청은 끝까지 둔다.

1. 앱 창이 하나 이상 열려 있다.
2. 세션이 `signed_in`이다.
3. 연결 상태가 `online`이다.

다시 참이 되면 목록과 상세를 곧바로 받는다. 알림은 GitHub 최소 간격이 지났을 때만 곧바로 받는다.

### 주기 (모두 조정 가능)

| 묶음 | 기본 주기                                      | 내용과 순서                                                                                                                                                                                                                                                           |
| ---- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 알림 | 60초. GitHub `X-Poll-Interval`이 더 길면 그 값 | 조건부 요청(ETag·Last-Modified). 304면 캐시를 두고 시각만 바꾼다. Inbox를 쓸 수 없는 로그인이면 받지 않는다.                                                                                                                                                          |
| 목록 | 5분                                            | 내 저장소 집합 → 내 저장소의 열린 PR·이슈 → 내가 올린 PR·리뷰 요청 → 할당된 이슈·내가 올린 이슈 → 나를 언급한 이슈 → 보고 있는 이슈 상세(패널이 열려 있을 때) → 스타한 저장소 → 기여 달력 → 최근 커밋. 열린 항목 수집이 캐시의 저장소 집합을 쓰므로 이 순서를 지킨다. |
| 상세 | 5분                                            | 상세 추적 저장소를 차례로 하나씩 받는다.                                                                                                                                                                                                                              |

- 수동 새로고침으로 알림을 받아도 다음 자동 알림 요청은 그 시각부터 `max(60초, X-Poll-Interval)` 뒤로 밀린다. 실패해도 같다.
- 같은 갱신 단위는 동시에 두 번 돌지 않는다. 진행 중인 요청에 합친다.
- 한 단위의 실패는 다른 단위를 막지 않는다.
- 갱신 사이에 로그아웃하면 그 결과로 동기화 시각을 바꾸거나 화면에 변경을 알리지 않는다.
- 로그아웃이나 계정 전환 전에 시작한 갱신의 결과는 캐시에 쓰지 않는다. 지운 뒤에 이전 계정의 정보가 다시 들어오지 않게 하기 위해서다.

### 요청 한도 보호

| 조건                                                          | 미루는 것                     |
| ------------------------------------------------------------- | ----------------------------- |
| graphql 또는 core 자원의 남은 양이 한도의 10% 미만(조정 가능) | 상세 추적 저장소의 자동 갱신  |
| graphql 자원의 남은 양이 한도의 5% 미만                       | 목록 자동 갱신                |
| search 자원의 남은 양이 한도의 10% 미만                       | 목록 자동 갱신 중 최근 커밋만 |

- reset 시각이 지나면 위 판정은 풀린다.
- 상세 화면에 들어갈 때와 이슈 상세 패널을 열 때의 즉시 갱신은 한도가 적어도 한다. 사용자가 직접 연 화면이기 때문이다. `online`이 아니면 하지 않는다. 수동 새로고침의 최근 커밋도 search 한도로 미루지 않는다.
- 내 저장소 집합에서 빠진 고정·연결 저장소의 접근 확인은 빠진 그 갱신에서 저장소마다 REST(core) 요청 1번이다. 빠진 뒤에는 집합 밖이라 다음 주기에 다시 묻지 않는다.
- `rate_limited`가 되면 자동 갱신을 멈추고, GitHub가 알려 준 시각 + 1초 뒤(시각을 모르면 60초 뒤)에 다시 판단한다.

### 수동 새로고침

상단 막대의 새로고침 버튼 또는 ⌘R(맥) / Ctrl+R(그 외). 지금 화면 주소로 범위를 정한다.

| 범위           | 받는 것                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------- |
| `home`         | 알림, 내가 올린 PR·리뷰 요청, 열린 항목, 기여 달력, 최근 커밋, 상세 추적 저장소 전부              |
| `inbox`        | 알림                                                                                              |
| `pulls`        | 내가 올린 PR·리뷰 요청, 열린 항목                                                                 |
| `reviews`      | 내가 올린 PR·리뷰 요청                                                                            |
| `issues`       | 할당된 이슈·내가 올린 이슈, 나를 언급한 이슈, 열린 항목, 보고 있는 이슈 상세(패널이 열려 있을 때) |

- 알 수 없는 주소는 `home`으로 본다.
- `signed_in`이 아니면 아무것도 하지 않는다. `offline`이면 연결을 한 번 확인하고, 그래도 `online`이 아니면 아무것도 하지 않는다.

### 마지막 동기화 시각

- 범위별로 마지막으로 받은 시각을 저장하고, 화면에는 그중 가장 최근 시각을 보여 준다. 앱을 다시 켜도 이 값으로 "N분 전 정보"를 보여 준다.
- 로그아웃하면 비운다. 세션 만료 중에는 남긴다.

| 연결 상태         | 상단 막대 문구                                                  |
| ----------------- | --------------------------------------------------------------- |
| `online`          | "동기화 N초 전". 받은 적이 없으면 아직 동기화하지 않았다는 문구 |
| `offline`         | "오프라인 · N분 전 정보"                                        |
| `rate_limited`    | "요청 한도 대기 · HH:MM에 재개". 시각을 모르면 시각 없이        |
| `session_expired` | "세션 만료 · N분 전 정보"                                       |

## 목록과 수치

- 화면의 수치는 목록 상한에 잘리지 않은 전체 개수다(GitHub `totalCount`·검색 `issueCount`). 받은 행이 전체보다 적으면 그 목록은 "불완전"으로 표시하고, 화면은 "GitHub에서 더 보기"를 보여 줄 수 있다.
- 목록 상한(조정 가능):

| 목록                                                                         | 상한                                           |
| ---------------------------------------------------------------------------- | ---------------------------------------------- |
| 저장소마다 받는 열린 PR·이슈(들어온 목록의 근거)                             | 각 50개, 최근 갱신 순                          |
| 저장소 상세의 열린 PR·이슈                                                   | 각 30개                                        |
| 내가 올린 PR, 리뷰 요청, 할당된 이슈, 나를 언급한 이슈, 내가 올린 이슈(검색) | 50개씩 최대 4페이지                            |
| 알림                                                                         | 50개씩 최대 5페이지                            |
| Home 고정 저장소 카드                                                        | 고정 순서 앞 4개                               |
| Home 최근 커밋                                                               | 5개(검색 한 페이지)                            |
| Home 내 PR                                                                   | 최근 갱신 순 5개                               |
| 이슈 상세의 코멘트                                                           | 오래된 것부터 100개                            |
| 이슈 상세의 라벨·담당자                                                      | 각 50개                                        |
| 이슈 상세의 닫는 PR / 연결·참조 타임라인 항목                                | 25개 / 오래된 것부터 100개                     |
| 이슈 상세 캐시                                                               | 200개. 넘으면 가장 오래전에 받은 것부터 지운다 |
| 새 이슈 양식의 라벨·담당자 선택지                                            | 각 100개씩 최대 5페이지                        |

- 열린 수가 0인 저장소는 열린 항목을 요청하지 않는다.
- 들어온 PR·이슈 수: 저장소 범위를 다 받은 저장소는 받은 행 중 내 것이 아닌 수로, 잘렸거나 아직 안 받은 저장소는 GitHub 전체 수에서 캐시가 아는 내 열린 항목 수를 빼서 센다.
- 상한에 잘린 저장소 범위를 다시 쓸 때는 기존 행을 줄이지 않고 합친다. 이번에 받은 범위(최근 갱신 순)의 가장 오래된 시각보다 최근인데 이번에 없는 행은 닫힌 것으로 보고 뺀다.
- 검색 목록이 첫 페이지부터 조직 제한으로 비어 왔으면 기존 목록을 지우지 않는다.
- 이슈 목록에는 PR을 섞지 않는다.

## Home

Home은 맨 위 인사말과 그 아래 Home 영역 열 개로 이루어진다. 영역 ID와 기본 순서는 활동 영역 `stats`, `pinnedRepos`, `contributions`, `recentCommits`, `myPullRequests` 다음에 할 일 카드 `reviewRequests`, `unreadNotifications`, `failedCi`, `unanswered`, `starChanges`다. 기본은 모두 켬이다. 수치는 한 줄을 다 쓰고, 나머지 영역은 창 너비 1100px 이상에서 두 열로 흐른다. 아직 받지 않은 값은 0이 아니라 "—"(또는 불러오는 중)로 보인다.

### 인사말

- 아바타, 이름(프로필 이름, 없으면 로그인 이름)을 넣은 인사, 부제, 오늘의 한마디.
- 오늘의 한마디: 번역 파일의 한마디 8개 중 (이 컴퓨터 달력 날짜의 일련번호 mod 8)번째. 같은 날에는 늘 같고 다음 날에는 다음 것이 나온다. 날짜가 바뀌면 1분 안에 바뀐다.

### 영역 목록 풀기

저장된 설정(`homeCards`)을 다음 순서로 푼다.

1. 빈 목록이면 기본 순서로 모두 켠다.
2. 모르는 ID는 버리고, 같은 ID가 두 번 있으면 처음 것만 쓴다.
3. 남은 목록에 활동 영역 ID가 하나도 없으면(활동 영역이 생기기 전에 저장한 설정) 활동 영역 다섯 개를 켠 채로 기본 순서대로 맨 앞에 넣는다. 기존 카드의 켬·끔과 순서는 그대로다.
4. 그 밖에 목록에 없는 영역은 켠 채로 기본 순서대로 끝에 붙인다.

- 활동 영역 ID가 하나라도 저장돼 있으면 3을 하지 않는다. 그래서 사용자가 활동 영역을 옮겨 저장한 순서는 다시 맨 앞으로 당겨지지 않고, 맨 앞 끼워 넣기는 설정을 한 번 저장한 뒤로는 일어나지 않는다.
- 설정 화면은 언제나 열 개 영역을 모두 순서대로 저장한다.

### 수치

| 수치      | 정의                                                                                                                      | "—"인 때                    |
| --------- | ------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| 커밋      | 최근 12개월 커밋 기여 수(GitHub `totalCommitContributions` 그대로). 기여 달력의 하루 수 합(이슈·PR 등 모든 기여)과 다르다 | 기여 달력을 받기 전         |
| 저장소    | 내 저장소 집합에서 포크·보관을 뺀 수(Repositories 화면 기본 필터와 같다)                                                  | 내 저장소 집합을 받기 전    |
| 열린 PR   | 내가 올린 열린 PR의 GitHub 전체 수(목록 상한에 잘리지 않음)                                                               | 내가 올린 PR 목록을 받기 전 |
| 연속 기여 | 기여 달력에서 기여가 1 이상인 날이 이어진 일수                                                                            | 기여 달력을 받기 전         |

- 연속 기여: 달력의 마지막 칸을 오늘로 본다(날짜 문자열이 아니라 칸 순서로). 오늘이 1 이상이면 오늘부터, 오늘이 0이면 어제부터 거꾸로 1 이상인 날을 센다. 어제도 0이면 0이다. 예: 오늘 0, 어제부터 5일 연속 1 이상, 6일 전 0 → 5.

### 고정 저장소 카드

- 고정 순서 앞 4개. 이름, 설명, 주 언어, 스타·포크 수, 소유자 아바타를 보인다.
- 캐시에 행이 없는 고정도 자리를 지키고 `#<ID>`와 "아직 불러오지 않음"으로 보인다. 접근 상태가 `unavailable`이면 "사용할 수 없음" 배지를 단다(사이드바와 같은 규칙).
- 카드를 누르면 앱 안 저장소 상세로 간다. 카드의 핀 버튼은 고정을 해제한다.

### 기여 달력

- 최근 12개월의 하루별 기여 수와 수준. GitHub 수준(`NONE`, `FIRST_QUARTILE` … `FOURTH_QUARTILE`)을 파랑 5단계로 칠한다.
- GitHub 달력의 주는 일요일에 시작하고 마지막 날이 오늘이다. 화면은 행을 월요일~일요일로 다시 놓고, 열은 월요일에 시작하는 주로 묶는다. 마지막 열이 이번 주가 되게 오른쪽에 맞추고 53주보다 오래된 주는 버린다.
- 달 이름은 열의 첫 날이 앞 열과 다른 달일 때 붙인다. 첫 달 이름이 다음 달 이름과 3열 미만으로 붙어 있으면 첫 것을 뺀다.
- 받을 때마다 통째로 바꾼다. 응답에 달력이 비어 오면 실패로 보고 기존 값을 둔다.

### 최근 커밋

- GitHub 커밋 검색(`author:<내 로그인>`, 작성 시각 최신 순)의 5개. 저장소 이름, 메시지 첫 줄, 짧은 SHA(7자), 작성 시각을 보인다.
- 줄의 아바타는 커밋 작성자의 것이다. 이미지가 없으면 작성자 로그인(GitHub 계정과 연결되지 않은 커밋은 커밋의 작성자 이름)의 첫 글자를 보인다. 둘 다 모르면 저장소 이름의 첫 글자다.
- 커밋 검색은 저장소의 기본 브랜치만 색인하고 몇 분 늦게 반영된다. 기본 브랜치가 아닌 브랜치에만 있는 커밋은 나오지 않는다. 받아들인 한계다.
- search 한도를 쓴다. 로그인 이름을 모르면 요청하지 않는다. 한 번도 받지 않았으면 불러오는 중 문구를 보인다.
- 줄을 누르면 GitHub 커밋 페이지를, "모두 보기"는 GitHub 커밋 검색(같은 조건)을 브라우저로 연다.

### 내 PR

- 내가 올린 열린 PR을 최근 갱신 순 5개 보여 주고, 수치는 GitHub 전체 수다. 행마다 표시 상태(위 "상태 값" 표)를 알약으로 단다: 초안 회색, 변경 요청 빨강, 승인 초록, 리뷰 필요 보라, 열림 초록 테두리.
- 행을 누르면 GitHub PR 페이지를 열고, "모두 보기"는 Pull requests 화면의 내가 올린 PR 탭으로 간다.

### 할 일 카드

| 카드              | 대상                           | 규칙                                                                                                                                                                                                                |
| ----------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 리뷰 대기         | 전체                           | 나 또는 내가 속한 팀에 리뷰가 요청된 열린 PR                                                                                                                                                                        |
| 안 읽은 알림      | 전체                           | Inbox의 안 읽은 알림                                                                                                                                                                                                |
| 실패한 CI         | (a) 상세 추적 저장소, (b) 전체 | (a) 상세 추적 저장소 중 기본 브랜치 최신 커밋의 CI가 `failing`인 것. 추적 순서를 지키고 중복은 한 번만. 상세를 아직 받지 않은 저장소는 빠진다. (b) 내가 올린 열린 PR 중 최신 커밋 CI가 `failing`인 것. 최근 갱신 순 |
| 응답 없는 새 기여 | 전체                           | 아래 판정                                                                                                                                                                                                           |
| 스타 변화         | 상세 추적 저장소               | 저장소별 최근 7일(조정 가능) 증가 수                                                                                                                                                                                |

- 리뷰 대기·안 읽은 알림·응답 없는 새 기여 카드는 목록을 최근 순 5개까지 보여 주고, 수치는 전체 개수다. 수치가 보여 준 개수보다 크면 "+N more"(표시 상한에만 잘림)를 보여 준다. 근거 목록이 불완전하면(`complete: false`) "GitHub에 더 있을 수 있음"도 붙인다. 숨긴 항목이 없는데 목록이 불완전하면 "GitHub에 더 있을 수 있음"만 보여 준다.
- 카드 항목을 누르면 GitHub 페이지를 브라우저로 연다. 저장소 단위 항목(실패한 CI (a), 스타 변화)은 앱 안 저장소 상세로 간다.

#### 응답 없는 새 기여 판정

내 저장소 집합의 열린 이슈·PR 중 다음을 모두 만족하는 것이다.

1. 작성자의 저장소 관계(`authorAssociation`)가 `OWNER`·`MEMBER`·`COLLABORATOR`가 아니다.
2. 쓰기 권한자(같은 세 관계)의 코멘트나 리뷰가 없다.
3. 작성자가 봇이 아니다(봇 제외는 기본 켬, 조정 가능).

- 코멘트와 리뷰는 각각 가장 최근 50개(조정 가능)만 본다. 메인테이너 답글은 대개 나중에 달리기 때문이다.
- 전체 코멘트·리뷰 수가 받은 개수보다 많은데 받은 것 중 쓰기 권한자가 없으면, 확인하지 못한 응답이 있을 수 있으므로 응답한 것으로 본다. 긴 토론 스레드는 "새 기여"로 세지 않는 보수적인 선택이다.
- 근거는 저장소마다 받은 열린 항목(각 50개)이다. 그보다 오래된 항목은 판정 대상에 들어오지 않을 수 있고, 이때 카드는 불완전으로 표시된다.

## 스타 증가

- 창은 이 컴퓨터 시간대의 달력 날짜 단위다. N일 창 = 오늘(진행 중) + 그 앞 N-1일.
- 일별 증가 = 창 안 각 날짜에 찍힌 스타 시각의 수. 오래된 날 → 오늘 순이고 마지막 칸이 오늘이다.
- 증가 합계 = 일별 증가의 합. Home의 7일 합은 상세 화면 30일 그래프의 마지막 7칸 합과 같다.
- 스타 시각은 상세 추적 저장소만 받는다. 가장 최근 페이지부터 거꾸로, 기준 시각(31일 전, 시간대 여유 하루 포함)보다 오래된 스타가 나올 때까지 받는다.
- 100개짜리 페이지를 20번(조정 가능) 받아도 기준 시각에 닿지 못했거나 GitHub가 깊은 페이지를 거부하면(422) "잘림"으로 표시한다. 이때 값은 실제보다 적을 수 있다.

## Inbox(알림)

- GitHub가 완료(done) 처리하지 않은 알림만 보여 준다. 읽음과 안 읽음을 모두 보여 주고 구분한다.
- 필터: 전체/안 읽음, 저장소별, 사유별(GitHub가 주는 `reason` 값 그대로).
- 행을 누르면 GitHub 페이지를 브라우저로 열고 그 스레드를 읽음 처리한다.
- 열 주소: 알림의 subject API 주소가 PR·이슈·커밋이면 해당 웹 페이지로, 릴리스면 릴리스 목록으로 바꾼다. 그 밖에는 종류별로 Discussion → discussions, CheckSuite·WorkflowRun → actions, 나머지는 저장소 첫 화면이다.
- 완료한 스레드는 (스레드 ID, 완료 당시 갱신 시각)을 기록한다.
  - 이후 받은 목록에 같거나 이전 갱신 시각으로 오면 숨긴다. 완료 요청 전에 시작한 갱신이 늦게 도착해도 다시 나타나지 않는다.
  - 더 새로운 갱신 시각(새 활동)으로 오면 다시 보이고 기록을 지운다.
  - 완전한 목록에 아예 없으면 GitHub에 반영된 것이므로 기록을 지운다.
- 알림 목록을 모든 페이지 받으면 통째로 바꾸고(빠진 스레드는 완료된 것), 페이지 한도에 잘렸으면 기존 알림을 지우지 않고 합친다.

## 쓰기 동작

### 막힘

다음이면 요청도 캐시 변경도 하지 않고 이유를 돌려준다. 우선순위 순이다.

| 이유              | 조건                                                       |
| ----------------- | ---------------------------------------------------------- |
| `session_expired` | 세션이 `expired`이거나 연결 상태가 `session_expired`       |
| `signed_out`      | 로그인하지 않음                                            |
| `offline`         | 연결 상태 `offline`                                        |
| `rate_limited`    | 연결 상태 `rate_limited`. 어차피 실패할 요청이기 때문이다. |

화면은 막힘이 있으면 스타·읽음·완료·클론 버튼과 이슈 상세의 반응·코멘트·닫기·다시 열기, 새 이슈 버튼을 비활성화하고 막힌 이유를 보인다. 이슈 쓰기의 규칙은 아래 "Issues" 절에 있다.

### 실행

1. 캐시를 먼저 바꾸고 화면에 다시 읽으라고 알린다.
2. GitHub에 요청한다. 스타 `PUT`/`DELETE /user/starred/{소유자}/{이름}`, 읽음 `PATCH /notifications/threads/{ID}`, 완료 `DELETE /notifications/threads/{ID}`.
3. 실패하면 캐시를 바꾸기 전 값으로 정확히 되돌리고, 다시 알리고, 실패와 화면에 보여도 되는 문구를 돌려준다.

- 쓰기 요청을 모아 두었다가 나중에 보내는 대기열은 없다. 오프라인에서 누른 쓰기는 버튼이 꺼져 있어 일어나지 않는다.
- 같은 대상(같은 저장소 ID, 같은 스레드 ID)의 동작은 앞 동작이 끝난 뒤(실패면 되돌린 뒤) 차례로 실행한다. 뒤 동작은 그때의 상태로 막힘을 다시 판단한다. 사용자의 마지막 의도(스타 → 취소)가 최종 상태가 되게 하기 위해서다. 다른 대상끼리는 기다리지 않는다.
- 캐시에 없는 저장소는 스타할 수 없다(요청 없이 실패).
- 캐시에 없는 스레드의 읽음·완료는 캐시를 바꾸지 않고 요청만 보낸다.
- 스타 수: 스타하면 1 늘고 취소하면 1 준다(되돌리면 원래 값).

## 저장소 상세 화면

- 어떤 저장소든 숫자 ID로 연다(`/repos/<ID>`). 내 저장소, 스타한 저장소, GitHub 검색 결과 모두 같은 화면이다.
- 화면에 들어가면 그 저장소가 상세 추적 대상이 되고, `online`이면 상세를 곧바로 받는다. 화면을 떠나면 추적이 끝난다(고정 저장소는 계속 추적한다). 한 번에 보고 있는 저장소는 하나다.
- 캐시에 저장소가 없으면(검색 결과 등) 상세 수집이 숫자 ID로 저장소를 찾아 저장하고, 화면은 다시 읽어서 보여 준다.
- 상세 정보: 머리글, 열린 PR 수와 목록, 기본 브랜치 최근 커밋 7개와 각 CI, 최신 릴리스와 릴리스 20개, 이 저장소에서 내가 올린 열린 PR, 열린 이슈, 언어 비율(상위 20개, 크기 순), 기여자 20명과 총 인원, 최근 30일 스타 추이.
- 기여자 총 인원: 페이지 링크의 마지막 페이지 번호로 `(마지막 페이지 - 1) × 20 + 마지막 페이지 수`. 빈 저장소는 0명, GitHub가 거부하면(너무 큰 저장소 등) 알 수 없음.
- 지표 카드 4개: 열린 PR 수, 최근 커밋 7개 CI 막대와 최신 커밋 기준 요약, 최신 릴리스 태그와 경과 시간, 최근 30일 스타 증가와 일별 그래프.
- Fork 버튼은 GitHub의 포크 페이지를 연다. 앱 안에서 포크를 만들지 않는다(현재 범위).
- 목록 항목(PR, 이슈, 커밋, 릴리스)을 누르면 GitHub 페이지를 연다. 앱 안 이슈 상세는 Issues 화면의 상세 패널에만 있고, 앱 안 PR 상세 화면은 현재 없다.

## Issues

### 목록

- 탭 네 개: 들어온 이슈(내 저장소 집합의 열린 이슈 중 내가 작성하지 않은 것), 나에게 할당(`assignee:@me`), 나를 언급(`mentions:@me`), 내가 올린 이슈(`author:@me`). 모두 열린 이슈만이고 PR은 섞지 않는다. 기본 탭은 들어온 이슈다.
- 네 탭의 수는 지금 탭이 아니어도 늘 함께 보인다. 각 수는 GitHub 전체 열린 수다(들어온 이슈는 "목록과 수치" 절의 들어온 수 규칙, 나머지는 검색 `issueCount`).
- 필터는 저장소·라벨·담당자 세 가지이고 셋을 모두 만족하는 행만 남긴다. 선택지는 지금 탭 목록에 있는 값(이름 순, 중복 없음)이다. 필터는 받아 둔 행에만 적용하고 GitHub에 다시 묻지 않는다.
- 정렬: 최신순(만든 시각, 기본), 최근 갱신순, 코멘트 많은 순. 같으면 최근 갱신 → 번호 큰 순으로 가른다.
- 탭·필터·정렬·연 이슈는 주소(`?tab=…&repo=<저장소 ID>&label=…&assignee=…&sort=…&issue=<저장소 ID>-<번호>`)에 둔다. 기본값은 주소에서 빼고, 모르는 값은 기본값으로 본다. 그래서 뒤로 가기·앞으로 가기가 화면 상태를 되돌린다.
- 탭을 바꾸면 저장소·라벨·담당자 필터를 푼다(선택지가 탭 목록에서 나오므로). 정렬과 연 이슈는 그대로 둔다.
- 행을 누르면 오른쪽 상세 패널에 연다. GitHub로 가지 않는다.

### 상세 패널

- 패널을 열면 메인에 그 이슈를 보고 있다고 알리고, `signed_in` + `online`이면 곧바로 상세를 받는다. 열려 있는 동안 목록 주기(5분)와 `issues` 수동 새로고침 때 다시 받는다. 닫으면 알림을 끝낸다. 같은 이슈를 다시 알리면 받지 않는다.
- 내용: 제목, 상태(열림 / 닫힘과 이유), 작성자, 본문, 라벨, 담당자, 반응, 코멘트(오래된 것부터 100개와 전체 수), 연결된 PR(상태 포함), 이 이슈를 참조한 커밋(같은 커밋은 한 번, 사라진 커밋은 뺀다). 메뉴에서 GitHub로 열기와 주소 복사를 할 수 있다.
- 본문·코멘트·미리보기는 GitHub가 만든 HTML을 정리한 뒤에 보인다. 본문 안 링크는 앱 창을 옮기지 않는다. http(s) 링크는 기본 브라우저로 열고, 그 밖의 링크는 눌러도 아무 일도 없다. 작업 목록 체크박스는 보이기만 하고 누를 수 없다. 불러오지 못한 이미지(만료된 비공개 이미지 주소 등)는 대체 문구로 바꾼다.
- 받은 상세는 캐시에 남아 오프라인에서도 보인다. 다시 받을 때 이슈·저장소를 찾을 수 없으면(삭제, 권한 상실, PR 번호) 이전 상세를 그대로 둔다.

상세가 캐시에 없을 때:

| 상황                                               | 표시                                                                                   |
| -------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 연결 상태가 `online`이 아님, 또는 조회 자체가 실패 | 오프라인·볼 수 없음 안내. 목록 행이 있으면 GitHub 열기 링크                            |
| `online`인데 15초(조정 가능) 안에 상세가 오지 않음 | "불러오지 못했습니다", 다시 시도(보고 있음 알림을 끝냈다가 다시 보냄), GitHub에서 열기 |
| 그 밖                                              | 불러오는 중                                                                            |

### 이슈 쓰기

막힘(세션 만료·로그아웃·오프라인·한도 대기)과 그 우선순위, 대기열 없음은 "쓰기 동작" 절과 같다. 막히면 요청도 캐시 변경도 하지 않는다. 그 밖의 거절 이유는 다음과 같고, 역시 요청 없이 돌려준다.

| 거절 이유                                              | 조건                                                                                      |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| `not_cached`                                           | 이슈 상세를 받은 적이 없다(노드 ID·권한을 모른다). 반응 대상이 상세에 없는 이슈·코멘트다. |
| `not_allowed`                                          | 아래 권한 판정이 거짓이다.                                                                |
| `empty_body` / `empty_title`                           | 코멘트 본문 / 새 이슈 제목이 비었거나 공백뿐이다(앞뒤 공백을 지운 제목을 보낸다).         |
| `repo_not_mine`                                        | 새 이슈 저장소가 캐시의 내 저장소 집합에 없다(캐시에 없는 저장소 포함).                   |
| `repo_fork` / `repo_archived` / `repo_issues_disabled` | 새 이슈 저장소가 포크 / 보관됨 / 이슈 기능이 꺼짐이다.                                    |

권한 판정(받은 상세 기준):

- 반응: GitHub의 `viewerCanReact`. 닫기: 열린 이슈이고 `viewerCanClose`. 다시 열기: 닫힌 이슈이고 `viewerCanReopen`. 거짓이면 버튼이 없다.
- 코멘트: 잠기지 않은 이슈는 언제나 가능하다. 잠긴 이슈는 그 저장소에 대한 내 권한이 `ADMIN`·`MAINTAIN`·`WRITE`일 때만 가능하고, 권한을 모르면 불가능하다. 불가능하면 입력란 대신 안내를 보인다.

동작별 처리:

| 동작               | 순서                                                                                                                                                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 반응 추가·취소     | 상세 캐시의 반응 수·내 반응을 먼저 바꾸고 알림 → GraphQL 요청 → 실패하면 바꾸기 전 상세로 정확히 되돌린다. 이미 그 상태면 캐시는 그대로 두고 요청만 보낸다.                                                                                |
| 코멘트             | GraphQL 요청 → 성공한 뒤에만 캐시를 바꾼다. 받아 둔 코멘트가 전체 수만큼 있으면 새 코멘트를 끝에 붙이고, 앞부분 일부만 받아 둔 상태면 수만 1 늘린다. 실패하면 입력한 글을 그대로 둔다.                                                     |
| 닫기·다시 열기     | 상세 캐시의 상태·이유를 먼저 바꾸고 → GraphQL 요청 → 실패하면 되돌린다. 성공하면 이슈 목록(`issues` 범위)을 뒤에서 새로 받아 열린 목록에서 빠지게 한다. 닫을 때 이유는 `completed`(기본)·`not_planned` 중 고른다.                          |
| 새 이슈            | `POST /repos/{소유자}/{이름}/issues`(제목, 비어 있지 않으면 본문, 라벨 이름, 담당자 로그인 최대 10명) → 성공한 뒤 "내 이슈" 목록에 바로 넣는다. 화면은 내가 올린 이슈 탭으로 옮겨 새 이슈를 상세 패널에 연다. 실패하면 양식을 그대로 둔다. |
| 라벨·담당자 선택지 | 새 이슈 양식에서 고른 저장소의 라벨·지정 가능한 담당자를 GitHub에서 바로 받는다(캐시하지 않음). 저장소 조건은 새 이슈와 같다.                                                                                                              |
| 마크다운 미리보기  | `POST /markdown`(gfm, 저장소 문맥) 결과 HTML을 정리해 보인다. 빈 글은 요청 없이 빈 결과다.                                                                                                                                                 |

- 같은 이슈에 대한 반응·코멘트·닫기·다시 열기는 앞 동작이 끝난 뒤(실패면 되돌린 뒤) 차례로 실행하고, 뒤 동작은 그때 상태로 막힘·권한을 다시 판단한다. 새 이슈는 같은 저장소 단위로 차례를 지킨다.
- 코멘트·새 이슈의 성공 응답은 요청 사이에 로그아웃·계정 전환이 있었으면 캐시에 쓰지 않는다(결과는 성공으로 돌려준다).
- 반응·닫기·다시 열기가 실패해도 요청 사이에 로그아웃·계정 전환이 있었으면 되돌리지 않는다. 그사이 다시 받은 상세를 이전 값으로 덮어쓰지 않기 위해서다.
- 새 이슈 저장소 선택지: 내 저장소 집합에서 포크·보관을 뺀 저장소, 최근 푸시 순. 이슈 기능이 꺼진 저장소도 보이지만 고를 수 없다.

### 만든 이슈의 유예

GitHub 검색은 새 이슈를 바로 색인하지 않는다. "내 이슈" 목록은 검색 결과로 통째로 바뀌므로, 앱에서 만든 이슈가 검색 반영 전에 사라지지 않게 다음을 지킨다.

1. 새 이슈를 만들면 (이슈 행, 만든 시각)을 기록하고 "내 이슈" 목록에 넣는다. 목록 전체 수를 1 늘린다.
2. 검색으로 "내 이슈"를 다시 쓸 때, 기록 중 검색 결과에 없고 만든 지 10분(조정 가능)이 안 된 이슈는 목록 앞에 남기고 전체 수에도 더한다.
3. 검색 결과에 나온 기록, 10분이 지난 기록, 읽을 수 없는 기록은 지운다.
4. 앱에서 그 이슈를 닫으면 기록을 지운다. 닫힌 이슈가 유예 때문에 열린 목록에 남지 않게 하기 위해서다.
5. 기록은 받아온 정보라 로그아웃·계정 전환 때 함께 지운다.

## 클론

- 대상 경로 기본값은 `<클론 기본 폴더>/<저장소 이름>`이다. 클론 직전에 다른 부모 폴더를 고르면 그 안에 저장소 이름 폴더를 만든다. 대상은 절대 경로여야 하고 파일 시스템 루트일 수 없다.
- 조건: `signed_in`이고 연결 상태가 `online`이어야 한다. 아니면 `signed_out`·`session_expired`·`offline`·`rate_limited`로 거부한다. HTTPS인데 토큰이 없으면 `signed_out`이다.
- 대상 경로 판정:

| 대상                                   | 동작                                                                                                                                            |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 없음                                   | 이번 클론이 폴더를 새로 만들고 클론한다.                                                                                                        |
| 빈 폴더                                | 그 폴더에 클론한다. 그 폴더는 앱이 만든 것이 아니다.                                                                                            |
| 파일, 심볼릭 링크, 비어 있지 않은 폴더 | 클론하지 않고 "이미 있음"을 돌려준다. 그 폴더가 git 작업 폴더면 원격 목록을 함께 주고, 원격이 같은 저장소를 가리키면 "이 폴더 연결"을 제안한다. |

- 실패하거나 취소하면 이번 클론이 새로 만든 폴더만 지운다. 원래 있던 빈 폴더(아래 토큰 잔존 예외 제외), 대상 밖의 어떤 폴더도 지우지 않는다. 취소하면 git 프로세스가 실제로 끝날 때까지(최대 5초, 그 뒤 강제 종료) 기다린 다음 지운다.
- HTTPS: 결과 폴더의 원격 주소는 `https://github.com/<소유자>/<이름>.git`이다. 토큰은 원격 주소, `.git/config`, 디스크 어디에도 남지 않는다. 클론 뒤 `.git/config`에서 토큰이 발견되면 실패로 끝낸다. 이번 클론이 만든 대상 폴더면 폴더째 지우고, 원래 있던 빈 폴더면 이번 클론이 만든 `<대상>/.git`만 지운다(내려받은 작업 파일은 남는다).
- SSH: 원격 주소는 `git@github.com:<소유자>/<이름>.git`이고 사용자의 SSH 설정과 키를 그대로 쓴다.
- 성공하면 그 폴더를 저장소에 자동으로 연결한다.
- 진행률은 git이 출력한 단계 이름과 0~100 퍼센트로 알린다.
- 같은 클론 ID로 진행 중이면 `already_running`으로 거부한다.
- 실패 코드: `invalid_request`, `invalid_target`, `already_running`, `auth_failed`(HTTPS 인증), `ssh_auth`(SSH 키·호스트 확인), `not_found`, `network`, `target_error`(폴더를 만들거나 쓸 수 없음), `git_error`(그 밖) 및 위의 막힘 코드. 화면은 코드를 번역하고, 토큰을 지운 git 원문을 상세로 보여 줄 수 있다.

## 로컬 연결

### 경로 정규화와 중복

- 실제 경로로 풀고(심볼릭 링크 해석, 없는 경로면 절대 경로), 끝 구분자를 떼고, 유니코드 NFC로 맞춘다. 맥·윈도우에서는 대소문자를 무시해 비교한다.
- (저장소 ID, 정규화 경로)가 같은 연결은 하나만 있다. 다시 연결하면 기존 연결을 돌려준다.
- 한 폴더가 여러 저장소에 연결될 수 있다(포크 클론: origin과 upstream).

### 자동 찾기

- 시점: 앱 시작, 클론 기본 폴더 변경, 세션이 `signed_in`이 될 때(처음 로그인·다시 로그인)와 `signed_in`인 채로 계정이 바뀔 때, 사용자 요청. 로그인 뒤 찾기는 로그아웃 상태에서 풀지 못한 원격을 풀고, 계정 전환으로 지워진 연결을 새 계정 기준으로 다시 만든다.
- 클론 기본 폴더 아래 깊이 2(바로 아래가 1, 조정 가능)까지 `.git`(폴더 또는 파일)이 있는 폴더를 찾는다. 숨김 폴더와 `node_modules`는 건너뛰고, 찾은 저장소 안으로는 내려가지 않는다. 폴더를 가리키는 심볼릭 링크는 따라가되 실제 경로 기준으로 한 번만 방문한다.
- 찾은 폴더의 원격 중 `origin`과 `upstream`만 본다. 둘 다 github.com 저장소를 가리키면 두 저장소 모두에 연결한다.
- 원격의 `소유자/이름` → 저장소 ID 풀이: 캐시의 저장소 이름과 대소문자 무시로 비교하고(`available` 우선), 없으면 `signed_in` + `online`일 때 `GET /repos/{소유자}/{이름}`으로 묻는다. GitHub가 이름 변경을 리다이렉트로 안내하므로 옛 이름도 같은 ID로 풀린다. 풀지 못하면 연결하지 않는다.
- 지금 클론 중인 대상 폴더는 건너뛴다.
- 기존 연결도 다시 확인해 상태를 바꾼다(아래 표). 겹친 찾기 요청은 하나로 합친다.

### 연결 상태 판정

| 폴더 상태                                                                             | 결과             |
| ------------------------------------------------------------------------------------- | ---------------- |
| 폴더가 없거나 git 작업 폴더의 최상위가 아님                                           | `missing`        |
| GitHub 원격이 없음                                                                    | `missing`        |
| 원격(`origin`·`upstream`이 있으면 그것, 없으면 모든 GitHub 원격)이 이 저장소를 가리킴 | `ok`             |
| 원격이 확실히 다른 저장소를 가리킴                                                    | `missing`        |
| 원격의 저장소를 풀 수 없음(오프라인 등)                                               | 지금 상태를 유지 |

- `missing`인 연결은 "다시 연결"을 보여 준다. 다시 연결은 새 경로를 직접 연결과 같은 규칙으로 검사한 뒤 연결을 옮긴다. 연결 ID가 바뀔 수 있다.
- 열기를 눌렀는데 폴더가 없으면 그 연결을 `missing`으로 바꾸고 열지 않는다.

### 직접 연결

| 검사                                                                        | 실패 이유        |
| --------------------------------------------------------------------------- | ---------------- |
| 절대 경로이고 있는 폴더인가                                                 | `path_not_found` |
| git 작업 폴더의 최상위인가(상위 폴더의 저장소를 이 폴더 것으로 보지 않는다) | `not_git`        |
| github.com 저장소를 가리키는 원격이 있는가                                  | `not_github`     |
| 저장소를 지정했다면 원격이 그 저장소를 가리키는가                           | `different_repo` |
| 원격의 저장소를 풀 수 있는가                                                | `unresolved`     |

### 연결 해제

연결(DB 행)만 지운다. 폴더는 어떤 경우에도 지우지 않는다. 계정 전환으로 연결이 지워질 때도 같다.

## 열기

- 대상: 에디터, 터미널, 파일 탐색기.
- 열 때마다 그 연결의 마지막 사용 시각을 바꾼다. 연결 목록은 마지막 사용 순이라, 여러 연결이 있으면 마지막에 쓴 폴더가 기본 선택이다.
- 에디터 고르기: 지정한 에디터 → 설정의 기본 에디터 → 처음 찾은 에디터. 설치된 것이 없으면 `no_editor`, 지정한 것이 없으면 `unknown_editor`.
- 감지하는 에디터는 고정 목록(VS Code, Cursor, Zed, JetBrains 계열, Sublime 등)이고 목록 순서대로 보여 준다.
- 터미널: 맥은 Terminal 앱, 윈도우는 Windows Terminal이 있으면 그것, 없으면 cmd 새 창, 리눅스는 `x-terminal-emulator` → `gnome-terminal` → `konsole` → `xfce4-terminal` 순. 없으면 `no_terminal`.

## 빠른 검색창 (⌘K / Ctrl+K)

- 검색어는 앞뒤 공백을 지우고 256자로 자른다. 2자 미만이면 결과가 비어 있다. 구역마다 최대 10개.
- 앱 안 항목(오프라인에서도 동작):
  - `#숫자`면 그 번호의 PR·이슈만 찾는다.
  - 그 밖에는 저장소(전체 이름·설명), PR·이슈(제목·저장소 이름)를 부분 일치로 찾는다. 저장소는 내 저장소 → 스타한 저장소 → 최근 푸시 순, PR·이슈는 최근 갱신 순.
- 명령: 화면 이동, 새로고침, 저장소 클론, 테마 변경, 언어 변경, 설정 열기.
- GitHub 저장소 검색: 입력이 300ms 멈춘 뒤 `online`일 때만 GitHub 전체 저장소를 검색한다. `online`이 아니면 요청하지 않고 그 구역에 오프라인·한도 대기를 표시한다. 결과를 누르면 숫자 ID로 앱 안 상세 화면을 연다. 실패해도 오류 문구는 화면에 보내지 않는다.

| 테마                   | `system` · `dark` · `light`         | `system`                                                             |
| Home 영역(`homeCards`) | (영역 ID, 켬 여부)의 순서 있는 목록 | 빈 목록 = 열 개 영역을 기본 순서로 모두 켬                           |

- 설정은 계정과 무관하다. 로그아웃·계정 전환에서 지우지 않는다.
- 일부 항목만 바꾸는 패치를 받는다. 모르는 키나 잘못된 값이 하나라도 있으면 아무것도 저장하지 않고 거부한다. Home 영역 목록에 같은 ID가 두 번 있으면 거부한다. 모르는 영역 ID는 저장은 되지만 Home이 풀 때 버린다.
- 저장된 값이 깨져 있으면 그 항목만 기본값을 쓴다.
- 클론 기본 폴더가 바뀌면 자동 찾기를 다시 한다.
- 언어 `system`: OS 로캘이 `ko`로 시작하면 한국어, 그 밖은 영어. 테마 `system`: OS 다크 모드를 따르고 바뀌면 바로 반영한다.

## 오류 보고

- 대상: 메인 프로세스의 처리되지 않은 예외·거부, 화면의 처리되지 않은 오류·거부.
- 같은 오류(프로세스 + 메시지 + 스택)는 10초 안에 다시 오면 묶고, 반복되는 동안 계속 묶는다. 한 실행에서 보고서는 최대 3개다. 그 뒤로는 띄우지 않는다.
- 내용: 앱 버전, OS 이름·버전, 프로세스(main/renderer), 메시지(2000자까지), 스택(16000자까지). 제목은 `[crash] <프로세스>: <메시지 첫 줄>`, 120자까지.
- 지우는 것(이 순서):
  1. 지금 토큰과 토큰 모양 문자열(`ghp_`·`gho_`·`ghu_`·`ghs_`·`ghr_`·`github_pat_`) → `<token>`
  2. 홈 폴더, `/Users/<x>`·`/home/<x>`·`C:\Users\<x>` → `~`
  3. github.com·api.github.com·raw.githubusercontent.com 주소 안의 소유자·이름 → `<owner>`·`<repo>`
  4. 캐시의 모든 저장소 행(내 저장소, 스타한 저장소, 고정한 남의 저장소, 지금 보는 저장소, 검색 결과)의 `소유자/이름` → `<repo>`, 로그인 이름 → `<user>`, 소유자·조직 이름 → `<owner>`, 내 저장소 이름만(3자 이상) → `<repo>`
- 이름 지우기는 단어 경계에서만 한다(`bob`이 `bobsled`를 망가뜨리지 않게). 스타한 저장소는 이름만으로는 지우지 않는다. 스택의 `node_modules/react` 같은 경로가 모두 지워지면 보고서가 쓸모없어지기 때문이다.
- 사용자가 미리 본 내용과 보내는 내용이 같다. 보낼 글은 메인이 가진 지운 보고서이고, 화면이 보낸 글이 아니다.
- 보내기: 빌드에 Gdesk 저장소(`소유자/이름`)가 있으면 그 저장소의 새 이슈 작성 페이지를 제목·본문을 채워 브라우저로 연다. 주소가 8000자를 넘으면 본문 끝을 잘라 "(truncated)"를 붙인다. 저장소가 없으면 내용을 클립보드에 복사한다.
- 자동 전송은 없다.

## 자동 업데이트

| 실행                                      | 방식                                                                                |
| ----------------------------------------- | ----------------------------------------------------------------------------------- |
| 개발 실행, 테스트 모드                    | 꺼짐(`disabled`)                                                                    |
| 빌드에 올바른 `소유자/이름` 저장소가 없음 | 꺼짐(`unavailable`)                                                                 |
| 윈도우, 리눅스 AppImage, 서명된 맥        | 자동: 뒤에서 내려받고 다음 재시작 때 적용. 준비되면 알린다.                         |
| 서명 안 된 맥, 리눅스 deb·그 밖           | 알림: 새 버전이 있다고 알리고 다운로드 페이지(최신 릴리스)를 연다. 내려받지 않는다. |

- 앱 시작 10초 뒤 처음 확인하고, 이후 6시간마다 확인한다. 이미 확인·다운로드 중이거나 준비됐거나 새 버전을 알린 상태면 뒤에서 다시 확인하지 않는다.
- 사전 릴리스와 낮은 버전으로는 업데이트하지 않는다.
- 업데이트 정보는 GitHub Releases에서만 받는다.

## 영구 규칙

- 사용자에게 보이는 모든 문구는 영어와 한국어를 함께 갖는다.
