# 보안 정책

Gdesk는 한 사람이 자기 컴퓨터에서 쓰는 앱이다. 앱 자체의 사용자·권한 체계는 없고, 무엇을 할 수 있는지는 GitHub 토큰의 권한이 정한다. 그래서 지킬 대상은 GitHub 토큰, 사용자의 폴더, 다른 계정의 데이터, 그리고 공개 오류 보고에 실릴 수 있는 개인 정보다.

## 보호 대상

| 대상                  | 위험                                                                                                   | 지키는 방식                                                                                                                                                                            |
| --------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GitHub 토큰           | 유출되면 비공개 저장소 읽기·쓰기, 조직 정보, 알림까지 넘어간다(`repo` 권한)                            | 메인 프로세스 메모리와 OS 보안 저장소에만 둔다. 아래 "토큰" 절                                                                                                                         |
| 사용자 폴더·클론 폴더 | 앱이 지우면 되돌릴 수 없다                                                                             | 클론 실패·취소 때 그 클론이 새로 만든 폴더만 지운다. 원래 있던 빈 폴더에 클론했는데 `.git/config`에 토큰이 남았으면 그 클론이 만든 `.git`만 지운다. 그 밖의 어떤 경로도 지우지 않는다. |
| 이전 계정의 데이터    | 다른 사람이 같은 컴퓨터에서 로그인하면 이전 계정의 비공개 저장소 이름·PR·알림·고정·연결이 보일 수 있다 | 로그인 성공 시 마지막 로그인 사용자 ID와 다르면 받아온 정보·고정·로컬 연결을 먼저 지운다.                                                                                              |
| 오류 보고 내용        | 공개 GitHub 이슈로 올라간다                                                                            | 토큰·경로·저장소 이름·사용자 이름을 지우고, 사용자가 미리 본 뒤에만 브라우저로 연다.                                                                                                   |
| 배포 빌드의 무결성    | 테스트용 덮어쓰기가 배포 빌드에서 켜지면 API 주소를 가짜 서버로 돌리거나 토큰을 주입할 수 있다         | 테스트 빌드 상수 + 실행 시 환경 변수, 둘 다 있어야만 켜진다.                                                                                                                           |

## 인증 흐름

### 토큰 직접 입력

1. 화면이 입력한 토큰을 `auth:loginWithToken`으로 메인에 한 번 보낸다.
2. 메인이 앞뒤 공백을 지운다. 비어 있으면 요청 없이 `empty_token`.
3. 아직 저장하지 않은 후보 토큰이므로 공용 요청 계층이 아니라 별도 fetch로 `GET /user`를 부른다(30초 제한).
   - 네트워크 실패·시간 초과 → `offline`. 원래 오류에는 요청 정보가 섞일 수 있어 버린다.
   - 401 → `invalid_token`.
   - 그 밖의 2xx 아닌 응답, 모양이 다른 응답 → `http_error`.
4. 사용자 정보와 `X-OAuth-Scopes`로 토큰 종류와 빠진 권한을 계산한다. 권한이 모자라도 로그인은 허용하고 경고한다.
5. 마지막 로그인 사용자 ID와 다르면 이전 계정의 데이터를 지운다. 그다음 사용자 ID 기록 → 토큰 저장 → 요청 계층의 세션 만료 해제 → `signed_in`.
6. 실패하면 시도 전 상태로 돌아간다. 화면에는 오류 코드만 가고 토큰·응답 원문은 가지 않는다.

### 브라우저 코드 로그인(OAuth 기기 인증)

1. 빌드에 공개 client ID가 없으면 `device_flow_unavailable`로 거부하고, 화면도 이 방식을 숨긴다.
2. `POST /login/device/code`(client ID, 권한 `repo read:org notifications`)로 사용자 코드와 인증 주소를 받는다. client secret은 보내지 않는다.
   - 네트워크 실패 → `offline`. 응답이 오류면 오류 코드 이름만(소문자·밑줄 64자 이하) 남기고 본문은 버린다.
3. 인증 주소는 `auth:openVerificationUri`로만 연다. http(s)가 아니면 열지 않는다.
4. GitHub가 준 간격으로 `POST /login/oauth/access_token`을 묻는다. `slow_down`이면 5초 늘린다. 만료 → `expired`, 거부 → `denied`, 취소 → `cancelled`, 그 밖 → `error`.
5. 토큰을 받으면 토큰 입력과 같은 3~5단계를 거친다.

### 세션 만료

- 어떤 요청이든 401을 받으면 요청 계층이 `session_expired`가 되고, 다시 로그인해 세션이 풀리기 전까지 GitHub로 요청을 보내지 않는다.
- 세션은 `expired`가 되고, 저장된 정보는 읽기 전용으로 남는다. 쓰기 동작·클론·자동 갱신·GitHub 검색은 막힌다.
- 토큰이 없을 때 요청하면 보내지 않고 같은 오류로 끝낸다.

## 권한 모델

앱 안의 역할은 없다. 아래는 프로세스·구성 요소별로 허용과 금지를 정리한 것이다.

| 주체                      | 허용                                                                                  | 금지                                                                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 화면(렌더러)              | `window.gdesk.invoke`/`on`으로 등록된 채널 부르기, 캐시 값 표시, `https:` 이미지 표시 | Node·Electron API, `fs`·`path`·`child_process`·`os`·`crypto` import, `src/main` import, 네트워크 요청(CSP `connect-src 'self'`), 다른 페이지로 이동, 새 창 |
| 프리로드                  | `invoke`·`on` 두 함수 노출                                                            | 그 밖의 API 노출, 토큰 다루기                                                                                                                              |
| 메인                      | GitHub API·웹, git 실행, DB·파일, 토큰                                                | GitHub 이외의 서버와 통신, 사용 통계·원격 로그 전송, 폴더 삭제(클론 정리 예외)                                                                             |
| git 자식 프로세스         | HTTPS 클론 동안 환경 변수로 토큰 받기, 시스템 SSH 설정 쓰기                           | 토큰을 인자·원격 주소·`.git/config`·자격 증명 도우미에 남기기                                                                                              |
| 테스트 빌드 + 테스트 모드 | 아래 "테스트 모드" 표의 덮어쓰기                                                      | 배포 빌드에서 같은 동작                                                                                                                                    |

### 화면이 보낸 값은 믿지 않는다

프리로드는 채널 이름을 가리지 않고 `ipcRenderer.invoke`에 그대로 넘긴다. 채널별 타입은 컴파일 때만 강제된다. 그래서 실제 경계는 메인 처리기의 입력 검사다.

- 저장소 ID: 양의 안전한 정수만(`assertRepoId`).
- 새로고침 범위: 정해진 이름 또는 `repo:<양의 정수>`만(`parseRefreshScope`).
- 설정 패치: 모르는 키·잘못된 값이 하나라도 있으면 전부 거부.
- 클론: 클론 ID, 저장소 ID, 소유자·이름 형식, 절대 경로 검사.
- 오류 보고: 화면이 보낸 메시지는 문자열인지 확인하고 길이를 자른 뒤 지운다. 이슈로 보내는 글은 화면이 보낸 글이 아니라 메인이 가진 지운 보고서다.
- 외부 링크: http(s)만 연다.

새 처리기도 이 원칙을 따른다. 화면에서 온 값을 그대로 SQL·파일 경로·명령 인자·GitHub 경로에 넣지 않는다.

## 토큰

| 단계   | 규칙                                                                                                                                                                                                                                                                           |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 생성   | 사용자가 GitHub에서 만든 개인 토큰을 넣거나, 기기 인증으로 받는다. 앱은 client secret이 없다.                                                                                                                                                                                  |
| 메모리 | 로그인 서비스 객체 안에만 있다. 요청 계층·클론 서비스·오류 보고 지우기는 공급 함수로 그때그때 받는다.                                                                                                                                                                          |
| 저장   | OS 보안 저장소로 암호화해 `<userData>/auth/credential.enc`. 리눅스에서 키링이 없으면 사용자 동의 시에만 0600 파일(`credential.insecure.json`, 폴더 0700), 동의하지 않으면 메모리만. 리눅스가 아닌데 암호화를 못 쓰면 메모리만. 테스트 모드 자동 로그인 토큰은 저장하지 않는다. |
| 사용   | `Authorization: Bearer` 헤더. 호출자가 넘긴 `Authorization` 헤더는 지우고 덮어쓴다. 페이지 링크 등 절대 주소는 API 주소와 같은 출처·경로 안일 때만 따라간다.                                                                                                                   |
| git    | HTTPS 클론 동안만 임시 askpass 스크립트(0700, 임시 폴더)가 환경 변수에서 읽어 출력한다. 스크립트 파일에는 토큰이 없다. 사용자 이름은 `x-access-token`. 사용자의 자격 증명 도우미는 `-c credential.helper=`로 비운다. 명령이 끝나면 임시 폴더를 지운다.                         |
| 폐기   | 로그아웃하면 메모리와 두 파일을 지운다. 저장 방식 선택은 남긴다. 암호화 파일을 풀 수 없으면 그 파일을 지운다.                                                                                                                                                                  |
| 갱신   | refresh token이 없다. 토큰이 만료·폐기되면 다시 로그인해야 한다.                                                                                                                                                                                                               |

토큰이 나타나면 안 되는 곳: 화면으로 가는 모든 응답·이벤트, 로그, 오류 보고, 클론 폴더(`.git/config`·원격 주소), git 명령 인자, 화면에 보이는 오류 문구.

이를 위한 장치:

- GitHub 요청 계층이 만드는 모든 오류 문구는 지금 토큰과 토큰 모양(`gh[pousr]_…`, `github_pat_…`)을 `[REDACTED]`로 바꾼다.
- 클론 결과의 git 오류와 "이미 있음" 원격 주소는 토큰을 `***`로 바꾸고, 주소의 `사용자:비밀번호@`를 지운 뒤 화면에 보낸다.
- 클론이 끝나면 `.git/config`에 토큰이 있는지 확인하고, 있으면 실패로 끝낸다. 대상 폴더를 이번 클론이 만들었으면 폴더째 지우고, 원래 있던 빈 폴더면 이번 클론이 만든 `<대상>/.git`만 지운다(내려받은 작업 파일은 남는다). 어느 쪽이든 토큰은 디스크에 남지 않는다.
- 쓰기 동작 실패 문구는 요청 계층 오류(이미 지운 문구)만 그대로 쓰고, 그 밖은 일반 문구로 바꾼다.
- GitHub 저장소 검색 실패는 상태 값만 돌려주고 문구를 보내지 않는다.

## 테스트 모드

테스트 모드는 빌드 상수 `__GDESK_TEST_BUILD__`(빌드 때 `GDESK_TEST_BUILD=1`)가 참이고, 실행 때 `GDESK_TEST_MODE=1`일 때만 켜진다. 배포 빌드는 상수가 거짓이라 환경 변수로 켤 수 없다.

| 테스트 모드에서만 되는 것                                                   | 배포 빌드에서                                               |
| --------------------------------------------------------------------------- | ----------------------------------------------------------- |
| `GDESK_TEST_API_BASE`, `GDESK_TEST_WEB_BASE`로 GitHub 주소 바꾸기           | 무시. 언제나 `https://api.github.com`, `https://github.com` |
| `GDESK_TEST_TOKEN`으로 자동 로그인(저장 안 함)                              | 무시                                                        |
| `GDESK_TEST_USER_DATA`로 사용자 데이터 폴더 바꾸기                          | 무시                                                        |
| `GDESK_TEST_GIT_BASE`의 가짜 git 저장소에서 클론                            | 무시                                                        |
| 에디터·터미널·파일 탐색기를 띄우지 않고 기록만(`local:testLaunches`로 읽기) | `local:testLaunches`는 오류를 던진다                        |
| `crash:testTrigger`로 일부러 오류 내기                                      | `{ accepted: false }`                                       |
| 업데이트 꺼짐                                                               | 빌드·OS별 방식                                              |

단위 테스트용 주소 바꾸기 통로(`createGitHubClientForTests`)는 Vitest 실행(`import.meta.env.MODE === 'test'`)이 아니면 생성자가 거부하고, 공개 모듈에서 내보내지 않는다. 배포용 팩토리는 옵션에 주소가 있어도 쓰지 않는다.

## 창과 링크

- 모든 창: `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, `webSecurity: true`.
- CSP: `default-src 'self'`, `script-src 'self'`, `connect-src 'self'`(개발 서버 웹소켓만 추가), `img-src 'self' https: data:`. 화면은 네트워크 요청을 할 수 없고, GitHub가 준 아바타 같은 https 이미지만 띄운다.
- 앱 창 안의 다른 페이지 이동은 모두 막는다(개발 서버 주소만 예외). 새 창 요청은 거부하고, http(s)면 기본 브라우저로 넘긴다.
- 외부 링크(`app:openExternal`, 오류 보고 이슈, 다운로드 페이지, 기기 인증 주소)는 `https:`·`http:`만 연다. `file:`, `javascript:` 등은 열지 않고 `opened: false`.
- 배포 빌드의 앱 메뉴에는 개발자 도구가 없다.

## 폴더

- 클론: 대상이 없으면 클론이 직접 만들고(원자적 생성), 그 폴더만 실패·취소 때 지운다. 대상이 이미 있는 빈 폴더면 쓰되 지우지 않는다. 예외로 그 폴더의 `.git/config`에서 토큰이 발견되면 이번 클론이 만든 `.git`만 지운다. 비어 있지 않으면 클론하지 않는다. 확인과 생성 사이에 다른 프로세스가 폴더를 만들었으면 앱 것으로 보지 않는다.
- 연결 해제, 다시 연결, 로그아웃, 계정 전환, 자동 찾기는 DB 행만 바꾼다.
- 자동 찾기는 클론 기본 폴더 아래를 읽기만 한다.
- 에디터·터미널 실행은 셸을 거치지 않고 인자 배열로 넘긴다. 경로에 특수 문자가 있어도 명령이 되지 않는다.

원격 감사 기록, 사용 통계, 원격 오류 수집은 없다. 로컬에 남는 기록은 다음뿐이다.

## 오류 보고의 개인 정보

- 지우는 것: 토큰과 토큰 모양 문자열, 홈 폴더와 사용자 폴더 경로, GitHub 주소 안의 소유자·이름, 캐시의 모든 저장소 행(내 것·스타·고정한 남의 저장소·본 저장소·검색 결과)의 전체 이름과 소유자·조직 이름, 로그인 이름, 내 저장소 이름(3자 이상).
- 로그인·DB가 준비되지 않았거나 읽다 실패하면 이름 없이도 토큰 모양·경로·GitHub 주소는 지운다.
- 보내기는 사용자가 미리 보고 누를 때만, 브라우저의 새 이슈 작성 페이지를 여는 것으로 한다. 앱이 직접 전송하지 않는다.
- 한 실행에 최대 3개, 같은 오류는 10초 안에 묶어 오류 고리로 대화상자가 쏟아지지 않게 한다.

## 배포 비밀값

- 서명·공증 비밀값(`CSC_LINK`, `CSC_KEY_PASSWORD`, `APPLE_*`, `WIN_CSC_*`)은 CI 비밀값으로만 두고, 값이 있는 것만 해당 OS 작업의 환경 변수로 넘긴다.
- OAuth 공개 client ID와 Gdesk 저장소 이름은 비밀이 아니다. 빌드 결과에 그대로 들어간다.
- client secret은 만들지 않고 어디에도 넣지 않는다. 공개 코드와 배포 파일에는 비밀을 숨길 수 없다.
