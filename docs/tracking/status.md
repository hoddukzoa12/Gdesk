# 현황

기준: 1단계(현황판 + 클론·열기)에 이어 두 번째 개발 주기(내장 OAuth client ID, Home 개편, 사이드바·상단 막대 개편, Issues 목록 + 상세 패널 + 쓰기)까지 합쳐진 상태. 버전 `0.1.0`, 원격 저장소 없음(아직 GitHub에 올리지 않음).

## 남은 일

우선순위 순서다. 1~3은 지금까지 만든 것을 배포하기 위한 일이고, 4부터는 다음 단계 범위다.

1. **저장소를 GitHub에 올리고 CI를 처음 돌리기.** 윈도우·리눅스 단위 테스트, 리눅스 화면 테스트, 세 OS 패키징을 이때 처음 확인한다. 윈도우 askpass(`.bat`)와 클론 취소 정리도 여기서 확인한다.
2. **배포 준비물 넣기.** 서명 인증서(맥·윈도우, 선택). OAuth App은 등록돼 있고 client ID가 코드에 기본값으로 들어 있어 따로 넣을 것이 없다.
   - 이번 주기 화면(Home 활동 영역, Issues 상세·쓰기)을 실제 github.com 계정으로 한 번 확인한다. 특히 커밋 검색 결과, 기여 달력, 비공개 저장소 이슈 이미지, 잠긴 이슈 권한 판정은 가짜 서버로만 확인했다.
3. **첫 릴리스와 업데이트 경로 확인.** 태그 → 초안 → 게시 → 설치된 이전 버전이 새 버전을 찾는지(OS별 방식).
4. 다음 단계 Git 작업: 최신 내용 받기(fetch/pull), 브랜치 전환, PR 체크아웃. 내장 git 실행기(`runGit`)는 명령 일반 실행부라 그 위에 더한다.
5. 다음 단계 PR 처리: 앱 안 PR 상세 화면, 코멘트·승인·머지. 들어오면 PR·알림 클릭이 앱 안 상세로 갈 수 있다. 지금 PR 목록 클릭은 GitHub 웹으로 간다. 앱 안 이슈 상세(Issues 화면의 패널)는 이번 주기에 만들었다. Inbox 알림과 저장소 상세의 이슈 항목은 아직 GitHub 웹으로 간다.
6. 앱 창을 닫아도 갱신, 메뉴바·트레이 아이콘, OS 알림. 지금 동기화 엔진은 창이 모두 닫히면 멈춘다.
7. Home의 사용자 정의 검색 조건 카드(예: 라벨이 bug인 열린 이슈). 지금 Home 영역은 정해진 열 개다.
8. 앱 안 포크 생성. 지금 Fork 버튼은 GitHub 포크 페이지를 연다.
9. 여러 계정 전환, GitHub Enterprise Server. 지금은 github.com 계정 하나이고, 계정이 바뀌면 이전 계정 데이터를 지운다.
10. 한국어·영어 외 번역(기여자가 `src/renderer/locales/<언어>/` 추가).
