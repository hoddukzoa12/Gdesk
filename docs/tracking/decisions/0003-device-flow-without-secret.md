# 0003. 비밀 키 없는 OAuth 기기 인증 + 개인 토큰 입력

## 맥락

Gdesk는 MIT로 공개되는 데스크톱 앱이다. 코드와 설치 파일에 넣은 값은 누구나 꺼낼 수 있으므로 OAuth client secret을 숨길 수 없다. 서버가 없으니 secret을 대신 쥐고 토큰을 바꿔 줄 곳도 없다. 그런데도 사용자가 토큰을 직접 만들지 않고 브라우저로 로그인할 길은 있어야 한다. 알림 API는 GitHub App 토큰이나 세분화 토큰으로 접근할 수 없다.

## 결정

- 브라우저 코드 로그인은 GitHub OAuth App의 기기 인증(Device Flow)을 쓴다. 공개 client ID만 필요하다. client ID는 빌드 때 `GDESK_GITHUB_CLIENT_ID`로 넣고, 비어 있으면 이 방식을 숨긴다.
- 개인 토큰 직접 입력도 함께 둔다. 기본(classic) 토큰을 권장하고, 세분화 토큰은 받되 Inbox를 쓸 수 없다고 알린다.
- 요청 권한은 `repo`, `read:org`, `notifications`이다. 권한이 모자라도 로그인은 허용하고 무엇이 안 되는지 알린다.

## 다른 선택지

- **Authorization Code + client secret을 앱에 넣기**: 공개 코드라 secret이 곧바로 공개된다.
- **GitHub App**: 사용자 토큰으로 알림 API에 접근할 수 없어 Inbox가 불가능하다.
- **토큰 입력만**: 사용자가 권한을 골라 토큰을 만드는 부담이 크다. 다만 client ID 없는 빌드(포크 등)의 대체 수단으로 남긴다.

## 결과

- refresh token이 없다. 토큰이 만료·폐기되면 세션 만료가 되고 다시 로그인해야 한다.
- 배포하려면 메인테이너가 OAuth App을 등록하고 Device Flow를 켜야 한다. 포크가 따로 배포하면 자기 OAuth App이 있어야 한다(승인 화면에 앱 이름·소유자가 보인다).
- `repo` 권한은 비공개 저장소 전체에 쓰기까지 허용하는 넓은 권한이다. 그래서 토큰을 메인 프로세스와 OS 보안 저장소에만 두는 규칙이 무겁다.
- 조직이 OAuth App 접근을 제한하면 그 조직 저장소가 보이지 않는다. 앱은 조직별 안내를 보여 줄 수만 있고, 조직 관리자의 승인이 필요하다.
