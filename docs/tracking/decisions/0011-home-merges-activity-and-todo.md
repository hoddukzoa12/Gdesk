# 0011. Home 하나에 활동 영역과 할 일 카드를 함께 둔다

## 맥락

1단계 Home은 할 일 카드 다섯 개(리뷰 대기, 안 읽은 알림, 실패한 CI, 응답 없는 새 기여, 스타 변화)뿐이었다. 두 번째 주기에서 GitHub 프로필 같은 활동 화면(인사말, 커밋·저장소·열린 PR·연속 기여 수치, 고정 저장소 카드, 기여 달력, 최근 커밋, 내 PR)을 더하기로 했다. 이미 할 일 카드의 순서·켜기·끄기를 설정으로 저장하고 있었고, 그 설정을 가진 사용자가 있다.

## 결정

- 새 화면을 따로 만들지 않고 Home 한 화면에 둔다. 인사말은 늘 맨 위이고, 그 아래 활동 영역 다섯 + 할 일 카드 다섯을 하나의 "Home 영역" 목록으로 다룬다. 기본 순서는 활동 영역이 먼저다.
- 설정 키는 기존 `homeCards`를 그대로 쓰고, 값에 열 개 영역 ID를 담는다.
- 활동 영역 ID가 하나도 없는 저장된 설정(이전 버전의 설정)은 풀 때 활동 영역 다섯 개를 켠 채로 맨 앞에 넣는다. 기존 카드의 순서와 켬·끔은 그대로다. 활동 영역 ID가 하나라도 있으면 끼워 넣지 않는다.

## 다른 선택지

- **활동 화면을 별도 메뉴로**: Home의 "매일 챙길 것" 성격을 지키지만, 같은 데이터(내 PR, 고정 저장소)가 두 화면에 나뉘고 메뉴가 늘어나며, 앱을 열었을 때 활동과 할 일을 한 번에 볼 수 없다.
- **새 설정 키(`homeSections`)로 옮기기**: 이름은 맞지만 설정 마이그레이션과 옛 키 처리 코드가 필요하다. 키 이름만 어긋나고 동작은 같다.
- **빠진 영역을 언제나 끝에 붙이기(1단계 규칙 그대로)**: 이전 설정을 가진 사용자에게 새 활동 영역이 할 일 카드 아래로 밀려 보이지 않는다.

## 결과

- Home 데이터(`query:home`)는 할 일 카드 집계와 활동 영역을 한 응답으로 준다. 활동 영역을 받는 갱신(기여 달력, 최근 커밋)은 목록 주기와 `home` 새로고침에 붙었다.
- 설정 키 이름 `homeCards`와 실제 의미(영역)가 다르다. 문서와 코드 주석이 이 차이를 설명해야 한다.
- 맨 앞 끼워 넣기는 "활동 ID가 하나도 없음"으로만 판정하므로, 앞으로 영역을 더 늘릴 때 같은 방식을 다시 쓰려면 판정 기준(어느 ID 묶음이 새것인지)을 새로 정해야 한다.
- 영역이 열 개라 좁은 창에서 Home이 길어진다. 수치는 한 줄을 다 쓰고 나머지는 1100px 이상에서 두 열로 흐른다.
