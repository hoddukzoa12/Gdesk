# 0009. 중앙 등록 파일 대신 파일 이름 규칙으로 자동 수집

## 맥락

기능(로그인, 사이드바, Inbox, 클론, 설정 …)마다 IPC 처리기, DB 테이블, 화면 라우트, 사이드바·배너 같은 화면 자리, 번역 파일이 생긴다. 이것들을 중앙 목록 파일에 한 줄씩 더하면 여러 기능을 동시에 만들 때 같은 파일을 고쳐 충돌이 잦고, 한 줄을 빠뜨리면 기능이 조용히 빠진다. 장기 프로젝트라 기능이 계속 붙는다.

## 결정

파일 이름 규칙과 Vite `import.meta.glob`으로 모은다.

| 무엇            | 규칙                                                                  |
| --------------- | --------------------------------------------------------------------- |
| IPC 처리기      | `src/main/**/*.ipc.ts`의 `registerIpc()`                              |
| IPC 계약        | `src/shared/ipc/<기능>.ts`의 타입 선언 병합                           |
| DB 마이그레이션 | `src/main/**/*.migration.ts`의 `migration`·`migrations`, ID 문자열 순 |
| 라우트          | `src/renderer/features/*/route.tsx`의 `routes`                        |
| 화면 자리(슬롯) | `src/renderer/features/*/slots.tsx`의 `slots`                         |
| 번역            | `src/renderer/locales/{en,ko}/<네임스페이스>.json`                    |

자동 수집이 불가능한 메인 시작 순서(`src/main/index.ts`)만 공유 파일로 남긴다.

## 다른 선택지

- **중앙 등록 파일(routes.ts, ipc/index.ts 등)**: 흔한 방식이고 한 파일에서 전체가 보인다. 그러나 동시 작업 충돌과 누락이 생긴다.
- **런타임 플러그인 로딩**: 서명·asar 구조와 맞지 않고, 타입 검사를 잃는다.

## 결과

- 새 기능은 자기 폴더 안 파일만 만들면 등록된다. 대신 전체 목록을 한눈에 보려면 파일을 찾아봐야 한다.
- 파일 이름을 틀리면(`foo.ipcs.ts`, `slot.tsx`) 아무 오류 없이 등록되지 않는다. 이름 규칙이 사실상 등록 API다.
- glob은 빌드 시점에 정해지므로, 모듈 최상위에서 `window.gdesk`를 부르거나 무거운 일을 하면 앱 시작 때 실행된다.
- 마이그레이션은 ID 문자열 순서가 적용 순서다. 기능끼리 접두사 범위를 나눠 써야 한다.
- Vitest의 디스크 모듈 캐시가 오래된 glob 결과를 돌려준 적이 있어 그 캐시를 꺼 두었다.
