# 0001. 범용 Git 클라이언트가 아니라 현황판 + 가벼운 Git

## 맥락

오픈소스 메인테이너는 여러 저장소의 PR·이슈·리뷰 요청·CI·릴리스·스타·알림을 매일 확인하는데, 이를 위해 GitHub 웹 탭을 여러 개 오간다. 데스크톱 Git 도구(GitHub Desktop, GitKraken, Fork, Tower, GitButler)는 커밋·브랜치 같은 한 저장소의 작업이 중심이고 이미 많다. 알림 전용 앱(Gitify 등)은 알림만 본다. 여러 저장소의 현황을 한 화면에서 보는 메인테이너용 GUI는 비어 있다. 공식 GitHub Desktop이 리눅스를 공식 지원하지 않는다는 점도 있다.

## 결정

Gdesk는 다중 저장소 현황판을 중심에 둔다. Git 작업은 클론과 로컬 폴더 연결, 에디터·터미널·파일 탐색기로 열기만 넣는다. 우선순위가 애매하면 "메인테이너가 매일 챙길 것을 덜 놓치게 하는가"로 판단한다.

## 다른 선택지

- **범용 Git 클라이언트(커밋·브랜치·diff·병합)**: 시장이 포화되어 있고, 같은 노력으로 기존 도구보다 낫기 어렵다. 현황판이라는 차별점이 묻힌다.
- **알림 전용 앱**: 범위가 좁아 CI 실패, 응답 없는 기여, 스타 추이처럼 알림으로 오지 않는 신호를 놓친다.
- **웹 확장·웹 앱**: 로컬 폴더 연결, 에디터로 열기, 오프라인에서 마지막 정보 보기가 불가능하다.

## 결과

- 데이터 모델은 "저장소 → PR·이슈·알림·CI" 중심이고, 로컬 작업 폴더 상태(변경 파일, 브랜치)는 모델에 없다.
- 지금 앱에서는 커밋·푸시·브랜치 전환·PR 체크아웃·fetch를 할 수 없다. 사용자는 연결된 폴더를 에디터·터미널로 열어 그 도구에서 한다.
- 내장 git 실행기는 명령 일반 실행부(`runGit`)로 만들어 두어, 다음 단계의 fetch·checkout을 그 위에 붙인다.
- PR 코멘트·승인·머지도 GitHub 웹으로 보낸다. 목록 클릭은 모두 GitHub 페이지를 연다.
