# 0007. 오류 보고는 미리 채운 GitHub 이슈로, 서버 없이

## 맥락

처리되지 않은 오류를 메인테이너가 알아야 고칠 수 있다. 그러나 Gdesk는 서버가 없고, GitHub 이외의 서버와 통신하지 않으며, 사용 통계를 수집하지 않는다. 오류 메시지·스택에는 사용자 홈 경로, 비공개 저장소 이름, 로그인 이름, 드물게 토큰 조각이 들어갈 수 있다.

## 결정

오류가 나면 대화상자로 지운 보고서(앱 버전, OS, 메시지, 스택)를 보여 준다. 사용자가 "보내기"를 누르면 Gdesk 저장소의 새 이슈 작성 페이지를 제목·본문을 채워 기본 브라우저로 연다. 실제 제출은 사용자가 GitHub에서 한다. 빌드에 Gdesk 저장소가 없으면 클립보드 복사로 대체한다.

## 다른 선택지

- **Sentry 같은 원격 오류 수집**: GitHub 이외의 서버로 데이터가 나가고 비용이 든다. 사용 통계 금지 원칙과도 맞지 않는다.
- **GitHub API로 앱이 이슈를 직접 만들기**: 사용자 토큰으로 사용자 모르게 공개 글을 쓰게 된다. 미리 보기와 사용자 의사가 흐려진다.
- **로컬 로그 파일만**: 메인테이너에게 닿지 않는다.

## 결과

- 보고서는 공개 이슈가 되므로 지우기 규칙(토큰, 경로, 저장소·소유자·로그인 이름)이 이 기능의 핵심이다. 지나치게 지우는 쪽을 택해 스택이 덜 유용할 수 있다.
- 이슈 주소 길이 한도(8000자) 때문에 긴 스택은 잘린다.
- 메인테이너는 자동 집계·빈도를 알 수 없다. 사용자가 보내 준 것만 본다.
- 오류 고리로 대화상자가 쏟아지지 않게 한 실행에 3개까지만 띄운다. 그 뒤의 오류는 보고되지 않는다.
