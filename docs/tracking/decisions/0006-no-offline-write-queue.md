# 0006. 쓰기 동작은 `online`일 때만, 대기열 없음

## 맥락

스타·스타 취소, 알림 읽음·완료는 GitHub 상태를 바꾼다. 앱은 오프라인·세션 만료·요청 한도 대기 중에도 저장된 정보를 보여 준다. 이때 사용자가 쓰기 버튼을 누르면 어떻게 할지 정해야 했다.

## 결정

연결 상태가 `online`이고 로그인되어 있을 때만 쓰기를 허용한다. 아니면 버튼을 끄고, 요청이 와도 아무것도 바꾸지 않고 이유를 돌려준다. `online`이면 캐시를 먼저 바꾸고(낙관적 갱신) 요청하며, 실패하면 정확히 되돌린다. 같은 대상의 동작은 순서대로 하나씩 처리한다.

## 다른 선택지

- **오프라인 쓰기 대기열**: 연결이 돌아오면 보낸다. 그 사이 GitHub에서 다른 기기로 상태가 바뀌면 화면과 GitHub이 어긋나고, 충돌 해결 규칙과 재시도·실패 알림이 필요하다. 사용자가 단순한 쪽을 골랐다.
- **비관적 갱신(응답 뒤 화면 변경)**: 버튼 반응이 느리다.
- **요청 한도 대기 중에는 허용**: 어차피 실패할 요청이다.

## 결과

- 오프라인에서는 스타·읽음·완료를 할 수 없다. 나중에 하라고 기억해 두는 기능도 없다.
- 클론도 같은 조건(로그인 + `online`)을 쓴다.
- 앱이 켜져 있는 동안 같은 대상의 연속 동작은 앞 동작 뒤에서 기다리지만, 막힘 상태에서 쌓아 두지는 않는다.
- 앱 안 PR 코멘트·승인·머지가 들어오면 같은 원칙을 따르는 것이 자연스럽다. 대기열을 도입하려면 이 결정을 바꿔야 한다.
