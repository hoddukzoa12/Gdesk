# 0012. OAuth client ID를 코드에 기본값으로 넣고 환경 변수로 덮어쓴다

## 맥락

브라우저 코드 로그인(기기 인증)에는 OAuth App의 공개 client ID가 필요하다. 처음에는 빌드 때 `GDESK_GITHUB_CLIENT_ID`로만 넣었고, 없으면 브라우저 로그인을 숨겼다. 그래서 `pnpm dev`, 로컬 `pnpm dist`, 변수를 설정하지 않은 CI 빌드는 모두 토큰 입력만 보였고, 메인테이너가 OAuth App을 등록한 뒤에도 빌드마다 값을 챙겨야 했다. client ID는 비밀이 아니어서 배포된 앱 안에서 누구나 볼 수 있다.

## 결정

- Gdesk OAuth App의 client ID를 `build/client-id.ts`에 기본값으로 둔다.
- 빌드 때 `GDESK_GITHUB_CLIENT_ID`가 없으면 기본값, 있으면 그 값, 빈 문자열이면 빈 값(브라우저 로그인 꺼짐)이 들어간다.
- 릴리스 워크플로는 저장소 변수나 비밀값에 값이 있을 때만 이 환경 변수를 설정한다. 둘 다 없을 때 빈 값을 넘기면 브라우저 로그인이 꺼진 채 배포되기 때문이다.
- client secret은 여전히 만들지 않고 어디에도 넣지 않는다.

## 다른 선택지

- **환경 변수만(기존)**: 포크가 원본의 OAuth App을 실수로 쓰지 않는다. 대신 개발 실행과 변수 없는 빌드가 모두 토큰 입력만 보여, 기본 사용 경험이 나쁘고 배포 준비물이 하나 늘어난다.
- **빈 값을 "기본값 사용"으로 해석**: 워크플로가 빈 값을 넘겨도 안전하다. 그러나 브라우저 로그인을 끈 빌드를 만들 방법이 사라진다.

## 결과

- 아무 설정 없이 빌드해도 브라우저 로그인이 켜진다. 배포 준비물에서 client ID가 빠졌다.
- 포크가 아무것도 넣지 않고 빌드하면 원본 Gdesk OAuth App으로 로그인한다. 승인 화면에 원본 앱 이름·소유자가 보이고, 그 OAuth App이 지워지거나 Device Flow가 꺼지면 포크 빌드도 브라우저 로그인이 실패한다. 포크는 자기 client ID를 넣거나 빈 값으로 빌드해야 한다.
- 화면 테스트 빌드는 가짜 값(`gdesk-e2e-client`)을 넣어 실제 OAuth App에 기대지 않는다.
- "빈 값 = 꺼짐"이므로 CI에서 값을 넘길 때는 비어 있는지 먼저 확인해야 한다.
