# 0008. 서명·공증·자동 업데이트·릴리스 자동화를 처음부터, 서명은 조건부

## 맥락

사용자는 처음부터 설치 파일, 서명 경로, 자동 업데이트, 릴리스 자동화를 갖추기를 골랐다. 그러나 맥·윈도우 서명 인증서는 아직 없다. 포크한 저장소도 인증서 없이 릴리스 워크플로를 돌릴 수 있어야 한다. 맥의 업데이트 장치(Squirrel.Mac)는 서명 안 된 앱의 자동 설치를 거부한다.

## 결정

- 서명 비밀값이 있는 OS만 서명(맥은 Apple 정보가 모두 있으면 공증까지)하고, 없으면 서명 단계만 건너뛰고 빌드는 성공한다.
- 맥 빌드는 서명 여부를 빌드 상수(`GDESK_MAC_SIGNED`)로 안다. 서명된 맥·윈도우·리눅스 AppImage는 뒤에서 내려받아 재시작 때 적용하고, 서명 안 된 맥과 리눅스 deb는 새 버전 알림과 다운로드 페이지만 연다.
- 인증서가 있는데 서명이 실패하거나, 서명됐다고 표시했는데 인증서가 없으면 빌드를 실패시킨다.
- 버전 태그를 푸시하면 세 OS 설치 파일을 Release 초안에 올리고, 메인테이너가 게시한다.

## 다른 선택지

- **인증서가 생길 때까지 서명·업데이트를 미루기**: 나중에 붙이면 이미 설치된 서명 안 된 맥 앱은 자동 업데이트 경로가 없다. 처음부터 알림 방식이라도 있어야 한다.
- **서명 없으면 빌드 실패**: 포크와 지금 저장소가 릴리스를 못 한다.
- **서명 안 된 맥도 자동 설치 시도**: Squirrel.Mac이 거부해 업데이트가 조용히 실패한다.

## 결과

- 지금 맥 사용자는 처음 열 때 Gatekeeper 경고를 보고(`xattr -cr`로 우회), 업데이트를 직접 내려받아야 한다. 서명 안 된 맥 앱은 자동 설치할 수 없다.
- 윈도우 서명이 없으면 SmartScreen 경고가 뜬다. 업데이트는 서명과 무관하게 자동이다.
- 초안을 게시하지 않으면 설치된 앱이 새 버전을 보지 못한다.
- 조건부 분기(서명·공증·`GDESK_MAC_SIGNED`)는 인증서가 없어 실제로 확인되지 않았다.
