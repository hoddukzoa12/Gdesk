# 0004. 시스템 git 대신 내장 git(dugite)

## 맥락

클론은 맥·윈도우·리눅스 모두에서 같은 방식으로 동작해야 한다. 사용자 컴퓨터에 git이 없거나(윈도우), 오래되었거나(맥의 Xcode git), 자격 증명 도우미가 토큰을 가로채 저장할 수 있다. HTTPS 클론에는 앱의 토큰을 명령 동안에만 넘기고 어디에도 남기지 않아야 한다.

## 결정

dugite로 git을 앱에 넣는다(GitHub Desktop 방식). HTTPS 인증은 임시 askpass 스크립트가 그 명령의 환경 변수에서 토큰을 읽어 출력하게 하고, 사용자의 자격 증명 도우미는 `-c credential.helper=`로 끈다. SSH는 시스템 SSH 설정과 키를 그대로 쓴다.

## 다른 선택지

- **시스템 git**: git 설치 여부·버전·설정에 따라 동작이 갈리고, 사용자의 자격 증명 도우미가 토큰을 키체인에 저장할 수 있다. 사용자가 이 방식을 기각했다.
- **순수 JS git(isomorphic-git 등)**: 큰 저장소 성능, SSH, 서브모듈 지원이 부족하다.
- **원격 주소에 토큰을 넣어 클론**: `.git/config`와 원격 주소에 토큰이 평문으로 남아 로그아웃 뒤에도 쓸 수 있고 사용자의 터미널 git과도 충돌한다.

## 결과

- 설치 파일이 커진다(OS·CPU별 git 실행 파일). 감수했다.
- git 실행 파일은 asar 안에서 실행할 수 없어 `app.asar.unpacked`에 둔다. 포장 설정이 패키지 안에 git이 있는지, 맥에서는 CPU가 맞는지 검사하고 아니면 빌드를 실패시킨다.
- dugite는 설치한 기계의 CPU용 git만 받으므로, 애플 실리콘에서 Intel 맥 앱을 만들 때 포장 중에 `node_modules`의 git을 바꿔 넣었다가 되돌린다. 그동안 같은 폴더의 테스트·개발 실행은 깨진다.
- 사용자의 git 설정(사용자 이름, 자격 증명 도우미)은 앱의 HTTPS 클론에 쓰이지 않는다. 결과 폴더는 평범한 `https://github.com/...` 원격이라 사용자의 터미널 git이 자기 자격 증명으로 쓴다.
- 앞으로의 fetch·checkout도 같은 실행기 위에 올린다. 시스템 git으로 바꾸려면 askpass·자격 증명 처리를 다시 설계해야 한다.
